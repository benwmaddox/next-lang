# T19: recursive functions (self-hosting step S0, part 1)

Historical Stage0 contract. For the self-hosted compiler, Ben superseded the
budget and live-region restrictions on 2026-10-28: see
[B1-recursion.md](B1-recursion.md). Keep frozen Stage0 behavior and its fixtures;
do not copy this historical machinery into B1.

Depends on T12. Same rules. Read DESIGN.md "How the compiler places values" (the Recursion bullet), "The native stack", and docs/PLAN.md "Self-hosting track" (S0 was added 2026-10-24 so S1, the self-hosted lexer and parser, can start as soon as M3 lands).

- **`recursive fn name(...)`** marks a function that may take part in a call cycle. A cycle is allowed only when every function in it is marked; otherwise T01's error stays, now naming the unmarked functions and suggesting `recursive`. Cycles through function values (T11) count: a function value's possible targets are part of the cycle check.
- **Native-stack budget:** every call into a recursive function checks the remaining native stack (the stack pointer against a limit stored in the job context) for at least that function's frame plus the frames of everything it calls without recursing (sizes from the optimised code actually built, plus a fixed margin); passing the budget fails the job with `recursion budget exhausted` at the call's line, never a crash. The budget is the process's native stack size minus a safety margin by default, and can be lowered in the manifest (`recursion_budget`).
- **No regions across a recursive call:** a recursive function may not keep any data-stack region alive across a call back into its cycle (relevant once M3 adds regions; in this task it applies to large fixed values over 4,096 bytes and anything else T13 puts on the data stack if T13 is already done). A violation is a build error naming the value; fixed values under that size on the native stack are fine and counted in the frame.
- Recursive functions can't be evaluated in `const` beyond the existing step limit; if T05's evaluator meets recursion, it counts each call as a step and keeps the limit.
- **Acceptance cases:** factorial and Fibonacci; mutual recursion (`is_even`/`is_odd`) with both marked; a cycle with one function unmarked (build error naming it); a cycle through a function value (build error unless all marked); a tree depth function over a `pool<Node<P>, N, P>` (recursive descent through ids); a deep recursion exhausting the budget (fails with the message and its line, exit 1, no segfault); a lowered `recursion_budget` making a moderate recursion fail; a recursive function used in a `const` (works within the step limit).
- Report: docs/tasks/T19-report.md.

## Corrections from Sol's S0 review (docs/reviews/sol-S0-r1.md), binding

- **Order:** T19 comes after T13 (it uses T13's job context and hidden context argument), not before M3.
- **Frame sizes, protocol:** build the program, read each function's final frame size from the object code clang produced (for example LLVM's `-fstack-usage`, or the `.stack_sizes` section), and use those numbers in the checks; the check is done in a small prologue that runs before the callee's frame is allocated, so later optimisation can't invalidate it. The check covers the callee's frame plus the deepest chain of non-recursive calls it can make (through function values too, using the largest target), compiler temporaries and alignment, plus DESIGN.md's 64 KB margin before foreign calls and enough to report the failure. Use the actual remaining usable stack (the stack pointer against the stack's real limit from the job context), not the total size. Test large frames, mutual recursion, recursion through function values, a foreign call near exhaustion, and both `-O1` and `-O3`.
- **Failure status:** `recursion budget exhausted` goes through `nl_fail` like any runtime failure (exit 1 from `nlc run`, the test child's failure code 70 under `nlc test`).
- **Compile-time evaluation:** purity is computed over whole call cycles (an effect anywhere in a cycle makes every function in it non-cacheable). The evaluator must not recurse on the Rust stack without a bound: give it an explicit frame stack or a checked depth limit, reporting a build error when passed. Tests: a terminating recursive `const`; a non-terminating one (step limit); mutual recursion where one function prints (refused); a real constant dependency cycle (still illegal).
- **Regions across cycles:** a recursive function may borrow a caller's large structures (a pool of nodes, a token list) through read or `write` parameters at every level; what it may not do is keep a region *it* created alive across a call back into its cycle, directly or through mutual and indirect cycles, including hidden result destinations and temporary copies. Tests: a recursive helper walking a caller-owned pool (allowed); a per-level large local kept across the recursive call (refused); the same through mutual recursion.
