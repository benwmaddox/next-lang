# R1: a runtime without per-operation heap use, buffered output, `match` on `byte`

Same rules (docs/PLAN.md). From DESIGN.md "Allocation calls are for arenas only" (Ben, 2026-10-25) and Claude's audit of runtime/nl_runtime.c.

1. **No heap use per operation.** Today `nl_fs_read_string` (`fs.read` into `Text`) mallocs a staging buffer the size of the destination's capacity and copies; `nl_fs_list` and `nl_fs_list_with_extension` calloc/realloc an entry array and strdup every name to sort before copying. Replace both: read straight into the destination's bytes and validate UTF-8 there (on failure, the destination's count stays 0, as T20/T23 require), or stage on the caller's data stack; gather directory names straight into the caller's list (filtering and the capacity check as now) and sort in place there, bounded by the list's capacity, with errors as today. Put the job context struct in the stack mapping's header instead of a `calloc`. Startup-only allocations (environment, file-name registry) may stay but are listed; test-only and `NLC_STACK_VERIFY`-only ones are marked as such in comments.
2. **A heap-call test:** build the runtime for tests with counting wrappers for `malloc`, `calloc`, `realloc`, `strdup` and `free` (or link-time `--wrap`), and assert that after `main` starts a program doing reads, listings, formatting, printing and collection work makes no heap calls (startup ones counted separately). Run it in both stack modes.
3. **Buffered standard output and error** (PLAN's small fix): a 64 KiB buffer each, flushed at exit, on `env.exit`, before a job failure is reported, before reading input, and per line when the stream is an interactive terminal; output order between stdout and stderr stays as written when both go to the same terminal. Measure bench/t32_number_output before and after.
4. **`match` on a `byte` value** with integer patterns (selfhost/lexer.nl casts to `int` today; remove that cast once it works) and keep the selfhost comparisons byte-identical.
- Report: docs/tasks/R1-report.md, with the remaining allocation sites listed and why each is allowed.
