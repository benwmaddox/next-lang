The three changes, in payoff order:

1. **Header-versus-program alias information, and a data-stack base cached until a real growth point.** Today every element store makes LLVM reload the base from the context header and re-check counts, because it can't prove the store missed the header. Either emit alias metadata that separates the context header's loads and stores from program storage (Sol's experiment: two sibling TBAA types under a private root, on the `nl_context_current_base` load and on typed user stores, including stores inside callees reached through `write` parameters), or implement the spec's SSA base/limit cache with reload only after a call or step that can grow; or both. Leaf calls that can't reach a growth point are not growth points. Never cache across a real growth point (a grow, a call that can grow, a later argument evaluation that can grow); never mark the base invariant for a whole function or job; never put `nonnull`/`dereferenceable` on descriptor anchors (they may be null); never tag raw `sys` accesses or core stores that may write the context as program storage. Start in `selfhost/compiler.nl::emit_location_pointer_materialization`, the scalar load/store and compound-assignment emitters, `selfhost/collections.nl`'s index/field/mutator emission, `params.nl` for descriptor parameters and `regions.nl` for cache lifetime.
2. **Reserve only the storage the emitter uses.** The region planner treats each `items[i]` receiver as a collection temporary and reserves whole unused copies of the list per iteration. Extend the receiver exclusion in `selfhost/regions.nl` (`region_node_is_temporary`, `region_node_is_collection_method_receiver`) to index receivers, driven by the actual emission/snapshot decision: reads that need a snapshot (for example an index expression that calls a mutator, or E2/E3 read snapshots) keep their storage.
3. **Top and peak in registers, published only where needed.** Scope exits that allocated nothing, and leaf returns without regions, currently publish the stack top every time. Keep top and peak in SSA and publish/fold them only at real synchronization points (calls that can reach the stack, growth, output and flush, failure), as the E3a1 design intends (`regions.nl::emit_region_scope_enter`/`exit`, `emit_current_top_*`, `compiler.nl::lower_scope_exit`, leaf-function exit lowering). High-water accounting (`NLC_STACK_STATS`) must stay exact.

Keep the core library's helpers visible to LLVM in the same module (no new opaque runtime calls in hot paths). Overflow and bounds checks all stay; removing proven-redundant checks and vectorisation are P1, not this step. Stage 0 (compiler/src) untouched.
