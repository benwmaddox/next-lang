# T25: byte buffers, source listing and a lexer-only reference (S1a prerequisites)

Same rules (docs/PLAN.md). From docs/reviews/sol-S1a-r1.md points 1 to 3 (read it for the evidence). Depends on T24.

1. **`Bytes` access and building.** Add `b[i] -> byte` (index a `long`, checked like list indexing) and `b.count()`; a growing `Bytes max N` builder like Ascii's: `grow` parameters, `try_append(bytes) -> Result<(), Full>`, `push(byte) -> Result<(), Full>` (proven forms without `Result` where the checker can show it fits, as for lists), appending a `Bytes` slice, all streaming into a reserved region with T15's checkpoint rules and T23's live-only rules. A slice of `Bytes max N` keeps max N but its length is the slice's; that's fine. Test repeatedly appending 256 file contents into one `Bytes max 64 MiB` builder (the S1 source buffer), overflow at the maximum, and aliasing (appending a slice of the builder to itself is refused or copies safely).
2. **UTF-8 validation with an offset.** `b.validate_utf8() -> Result<(), Utf8Error>` where `Utf8Error { valid_up_to: long }` follows Rust's `str::from_utf8` semantics exactly (the byte offset of the start of the first invalid sequence; overlong encodings, surrogates, code points above U+10FFFF and truncated sequences are invalid). Also `b.to_text()` returning that error. Test each invalid class.
3. **Source listing that matches the Rust driver.** `fs.list_with_extension(dir, ext: Ascii, entries: write list<DirEntry, N>) -> Result<(), IoError>`: keeps only entries whose extension, by Rust's `Path::extension` rule, is exactly `ext` (so `a.nl` yes, `.nl`, `a.NL` and `a.nl.bak` no), classifies each by following symlinks (a dangling symlink is `Other`), filters before checking capacity (so any number of ignored entries is fine), and sorts by raw bytes. Rust's driver keeps only regular files after following symlinks; S1 then filters kind == File itself. Rooted I/O stays as T20 defines it: S1 supports relative package paths within the working directory only (state that in docs/syntax-tree-format.md's command section). Tests: `.nl`, `a.nl`, `.NL`, an `x.nl` directory, regular/dangling/directory symlinks, 256 and 257 sources, 10,000 ignored entries, a name with invalid UTF-8.
4. **A lexer-only reference in the Rust compiler:** `nlc lex <package>`: the driver's listing, per-file and package byte checks, UTF-8 check, lexing and token limits exactly as `nlc parse` does them, then prints the token dump (same format as `--tokens`) without parsing; exit statuses as `nlc parse`. Share code with `parse` so the two can't drift; document it in docs/syntax-tree-format.md. `nlc parse --tokens` keeps its current meaning.
