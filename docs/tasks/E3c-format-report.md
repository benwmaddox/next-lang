# E3c formatter implementation

## Scope

The self-hosted compiler now has a dedicated `selfhost/format_text.nl` module
for checking and lowering `str`, `str_hex`, `str_bin`, `pad`, `pad_right`,
`pad_zero`, and `ascii_upper`. Output values are written into the expression's
caller-reserved aggregate destination.

`str` accepts `int`, `long`, and `byte`; `str_hex`, `str_bin`, and
`pad_zero` use the same numeric types. Decimal bounds are 11 bytes for `int`,
20 for `long`, and 3 for `byte`; a constant expression narrows the result to
its actual formatted length. Signed minima are formatted in the negative domain,
so computing the magnitude does not overflow. Hexadecimal output uses lowercase
digits and binary/hex retain a leading minus sign.

Before interning an inferred output type, the checker includes the 8-byte
`Ascii` or 16-byte `Text` header in its capacity limit. Text padding checks its
byte addition before evaluating it; oversized constant widths produce a build
diagnostic rather than wrapping or failing a compiler table.

`pad` and `pad_right` preserve the input string kind. `Ascii` width counts
bytes; `Text` width counts code points and stores byte length and code-point
count separately. `ascii_upper` copies into a fresh `Ascii` result and changes
only ASCII lowercase letters, preserving NUL and all other bytes.
Text padding emits the UTF-8 validity assertion in test builds.

The new `core/text_format.nl` helpers write directly to caller-provided
destinations. They use bounded `for` loops, do not allocate or call C runtime
formatters, and avoid overflowing on the minimum signed `long`. Core embedding
was regenerated by the compiler owner.

`str(bool)` remains rejected because Stage 0 rejects it and the E3c scope does
not add that form; boolean formatting is reserved for E3d3 interpolation.

## Focused validation

Core bootstrap passed after the reserved parameter name `width` was renamed to
`target_width`. With `CARGO_TARGET_DIR=/home/ben/.cache/next-lang/target`,
`NLC_TEST_JOBS=1`, and `ulimit -v 8000000`, ran:

```sh
scripts/compare-selfhost.sh --build --only "tests/e3/e3c_*" --only "tests/e1/unsupported_type_ascii_*" --only "tests/e1/unsupported_type_bytes_*" --only "tests/run/t14_ascii_cast_failure" --only "tests/run/t14_ascii_expect" --only "tests/run/t16_bytes_view_return" --only "tests/run/t16_bytes_view_store"
```

The script rebuilt selfhost and embedded core from the then-current sources, then
compared 35 selected packages: 15 build matches, 10 diagnostic matches, one
intentional reject, eight expected-output matches, one expected rejection, and
zero mismatches or unsupported packages. This includes the exact
constant-derived capacity cases `str(7)`, `str(-1)`, and `str(1 + 2)`. Stage 0
accepts the capacity cases.

The historical selector above has a path typo: it names
`tests/run/t14_ascii_expect`, while the package is
`tests/test/t14_ascii_expect`. That invocation did not select the test
package. The later 727-package release-reference comparison selected the
correct package and it matched; this is evidence for ordered-Ascii
expectations, not a dedicated Text-padding corruption assertion. No such
padding-specific corruption check is claimed here. The current registry has
728 packages, including 30 new E3c fixtures, and the fresh complete O1/O3
suite is still running; final acceptance remains pending as recorded in
[E3c-report](E3c-report.md).
