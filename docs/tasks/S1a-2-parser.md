# S1a-2: the self-hosted parser and tree dump (self-hosting step S1a, part 2)

Depends on S1a-1 and T26. Read docs/PLAN.md "Self-hosting track", docs/research/selfhost-architecture.md section 5.1 (revision 2; where it describes the Rust parser before T22, the current parser.rs wins: every counted path is limited to 1,000 and `else if` chains are parsed iteratively), docs/reviews/sol-selfhost-arch-r1.md points 5 to 9, docs/syntax-tree-format.md, compiler/src/parser.rs, ast.rs, syntax_dump.rs and driver.rs, and S1a-1's code and report.

Extend `selfhost/` so `nlc run selfhost -- parse <package> [--tokens] [--tree]` reproduces `nlc parse` **byte for byte** (stdout, stderr, exit status) for every flag combination: none (syntax errors only), `--tokens`, `--tree`, both (with the `== tokens ==` / `== tree ==` headers).

## Design (binding)

- **Node storage:** one postorder node list per package on `main`'s data stack (children before their parent; every subtree contiguous; a subtree size per node, so no child-edge array), plus an extra-data list and a literal-value list, as the research report's node-encoding table describes (main token for names; flags for booleans and small enums; extra data for second names, generic and index lists, ranges, byte strings, effect paths and `expect` sources; synthetic nodes with explicit spans). Spans and token starts are file-relative. Nothing is added that would change the reference's node, edge or work counts.
- **Parser:** recursive descent mirroring parser.rs function by function, so tokens are consumed and errors raised in the same order. Recursion only along paths parser.rs counts (each limited to 1,000 now); mark those functions `recursive`. `else if` chains with explicit frames, as parser.rs now does. Port the completed-tree nesting walk (`expression_nesting_exceeded`) task for task over each outermost expression's postorder range, pushing children in the same order and running it at the same moment, with the same diagnostic span rule.
- **Native stack:** measure the recursion budget each counted path needs at its 1,000 limit (T19's report gives the method) and show at least a 2x margin under the default budget; any path that misses it moves to explicit frames.
- **Integer literals:** decode magnitudes into four 32-bit limbs held in non-negative `long`s; detect overflow past 2^128 - 1 with Rust's exact message; range endpoints follow Rust's i128 rule; print magnitudes in decimal by dividing by 10^9 limb by limb.
- **Limits and order:** the package flow continues in driver.rs's order after lexing: per-file tree counting, then cumulative node, edge and work limits, each at the point Rust checks it, with Rust's messages (sol-selfhost-arch-r1.md point 5).
- **Printer:** preorder from postorder with an explicit `{node, depth}` stack (children found right to left by subtree sizes and pushed so the first child pops first); output streamed through the 1 MiB `Bytes` buffer; JSON escaping and field order exactly as syntax_dump.rs.
- **Decoded values:** byte-string and string values are printed decoded, so escape-decoding bugs that the token dump couldn't see are compared here.

## Comparison and acceptance

- Extend scripts/compare-selfhost.sh with `--parse` (all four flag combinations) over tests/run, tests/test and tests/parse/cases, and over S1a-1's directed and mutation cases; keep the `--tokens`/lex comparison.
- Parser-specific directed cases: every node kind and field in syntax-tree-format.md at least once; every counted nesting path at 1,000 and 1,001 (parentheses, unary, binary chains, calls, casts, blocks, types, `if`/`match`, `else if`); the completed-tree walk's error span for a binary chain; integer literals at 2^64 - 1, 2^64, 2^127, 2^128 - 1, 2^128 in decimal, hex and binary, with underscores, `L`/`l` suffixes, negative literals and refinement endpoints at the i128 edges; synthetic nodes (`default()`, match-arm blocks, `else if` blocks); `pool<T, N, Owner>` argument order; a type-error package (must still dump: the checker never runs); a package where a later file has a syntax error (no stdout); node, edge and work limits at N and N + 1.
- A mutation pass with a new fixed seed (a few hundred cases) under `--parse --tree`.
- The 54,145-line benchmark under `parse --tokens --tree`: time and peak memory for both, reserved versus touched for the self-hosted parser.
- Report: docs/tasks/S1a-2-report.md with the same sections as S1a-1's (implementation, comparison, timing and memory, forced boilerplate versus missing features, compiler fixes, wanted features).

## Corrections from Sol's review (docs/reviews/sol-S1a-2-r1.md), binding; they override the text above where they differ

Read the review for the evidence (file and line) behind each point.

1. **Exceptional fields:** write down and implement the recipe for every field that isn't a token's raw spelling: `Test` names (decoded string, where `\xFF` becomes U+00FF as the lexer's value does), dotted type names assembled by `type_name_inner` and its synthesised `()`, `fn` and `TextBytes`, effect paths (identifiers joined without whitespace), `Expect source` (`expect ` plus the expression slice), synthetic `default`, decoded byte-string values (raw bytes kept). Test dotted paths with whitespace, grouped/unit/function types, `Text max N bytes max M`, escaped test names and odd spacing after `expect`.
2. **Don't mutate the lexer's tokens:** `>>`/`>>=` splitting for nested generics must use virtual split pieces in a parser cursor (or a separate mutable view with stable references to the original tokens), so the token dump, stored token indexes and token/work counts are unchanged. Test nested generics ending in `>>` and `>>=`, an adjacent `=`, ordinary shifts and the error columns.
3. **Per-file order:** restructure loading so each file is read, checked, lexed, token-checked, parsed and tree-counted (with the package limits) before the next file is read, exactly as driver.rs does, keeping successful data for the final output. Tests: an earlier file's syntax error against a later file's lexical error, and against a later file's read or byte-limit error.
4. **The completed-tree walk:** reconstruct its Expr, Block and Type tasks from the encoding: blocks push the tail before statements, types visit the AST's argument groups (not dump order, notably for `pool`), casts push the value before the type, match patterns are skipped. Keep operator-token anchors separately from parenthesised spans. Tests: competing over-limit branches, statement against tail, capacity and function-type expressions, a root `print` against an ordinary root, and a later syntax error competing with the walk.
5. **Native-stack proof for the whole chain:** the counted paths can nest inside one another, and malformed input can build frames before the walk rejects it, so measure mixed inputs (successful and rejected) combining paths at their limits, under the optimisation levels the build uses, and bound the whole active chain with a 2x margin. Mark every function in each recursive cycle `recursive`. T19 forbids large locals and temporaries across recursive calls, so scratch and frame lists are caller-owned with per-call checkpoints. Paths that miss the bound move to explicit frames.
6. **Postorder construction with replacement:** specify how parents that replace an earlier node are built (a `Name` becoming a `Call`, qualified-case calls, struct literals replacing their name) using delayed roots or checkpoint-and-replace, so no ghost nodes remain and every subtree stays contiguous; assert contiguity and counts. Tests: `f()`, indirect calls, `E.C(1)(2)`, shorthand fields, grouped postfix chains. Bound side tables and scratch so an internal `Full` can never come before Rust's later syntax diagnostic.
7. **Literal tests, expanded:** malformed separators, digits and prefixes (validated before radix conversion, as parser.rs does); expression `-0` against range `-0` (ranges normalise negative zero); signed range overflow; `stack_peak` byte-unit scaling and its own overflow message; decoded output with valid UTF-8 from hex escapes, isolated invalid bytes, truncated sequences and escapes crossing the 1 MiB output boundary.
8. **Edges:** edges always equal nodes minus files, and both limits are 2,000,000, so the node limit always fires first; document that invariant (don't test an unreachable edge overflow). Test reachable node and work boundaries and paired failures (syntax before tree counting, per-file against cumulative, nodes before work), with no dump flags as well, since Rust counts trees then too.
9. **Coverage inventory:** derive the directed cases from syntax_dump.rs (every node kind, every enum alternative of each field, absent and present optional children), wrapped so each parses; add `Take` and the `grow` parameter mode to docs/syntax-tree-format.md, which omits them. Wire `--parse` into compiler/tests/selfhost.rs. Narrow the harness's tool-failure exception to the OS message text only (same prefix, same status, same message up to the OS error). Fields the dump omits (such as `ByteString`'s hex-origin flag) are kept in the encoding for S2.
10. **Diagnostics with long names:** stream token-bearing diagnostics into the error buffer rather than through a bounded `Ascii max 160` message (parser messages include arbitrarily long names); duplicate-generic detection uses bounded source-slice hashing in caller-owned scratch. No new core language feature is needed; use concrete capacities where inference is awkward.
