# T23: touch only live collection elements (M3 follow-up, before T17)

Same rules (docs/PLAN.md). From docs/research/selfhost-architecture.md 2.3(b) and section 6 item 1, with the safety rules in docs/reviews/sol-selfhost-arch-r1.md points 2 to 4.

DESIGN.md says a large local collection is committed only as it's used (pages cost RAM when first written). Today the emitter breaks that: an empty `list<long, 6000000>` holding one element touches 48 MB, because empty literals, construction, copies and returns write or move the full capacity. This task makes the rule hold everywhere.

## The rule

No code path writes, reads, copies, compares, hashes or prints a collection past what its representation needs:

- **list, queue, ring:** an empty one writes only its header (count, and for queue/ring head and length). Copies, returns, equality, printing and hashing touch only the live elements (for a wrapped queue or ring, both live segments).
- **map and set:** lookup reads 8-byte bucket entries first (zero meaning empty, negative a tombstone), so the bucket array must be initialised to empty, not only the occupancy flags; insertion-order records, hashes and values are touched only as used. Either initialise buckets and flags in full (they're the per-slot metadata, much smaller than keys and values; state the bytes per slot) or redesign probing so untouched buckets are never read; say which and why. Copies keep or rebuild buckets, tombstones, hashes and insertion order exactly (iteration order must not change).
- **pool:** add a high-water mark (the end of the initialised slots). Slots at or above it are free with generation 1 and need no writes; the free list holds only slots below it. Lookup, iteration, equality and printing check the high-water mark before reading a slot's flag or generation, so a stale id into an untouched slot is reported as stale, never read from garbage. Removed-slot generations, retirement (a slot whose generation would overflow is never reused) and the free-slot order are kept through copies and resets.
- **Construction and copies:** struct and enum construction initialise collection fields by the rules above, not with a memset of the whole destination; copies and returns move only live parts; returning a local collection builds it in the caller's destination (as T14 does for Ascii), not a callee local plus a copy.
- **Whole-value loads and stores:** audit every place the emitter loads or stores a whole collection value (equality and printing load whole operands today), not just explicit memcpy/memset calls. Include nested collections (a struct of lists, a list of structs holding lists), enum payloads with collections, and fixed arrays and grids (which are always fully live: their rule stays full initialisation).
- **Runtime:** `fs.read` and `fs.list` in runtime/nl_runtime.c clear their whole destination on entry and on failure; make them set the count only (and clear only what they wrote, if anything).

## Acceptance

- Maximum RSS (measured with /usr/bin/time from a built binary) for: a local `list<long, 6000000>` holding one element (48 MB today; target under 2 MB above an empty program), the same as a struct field, a returned `list<long, 2000000>` (32 MB today), an empty `map<long, long, 1000000>` and `pool<T, 2000000>` holding one element each (state the metadata bytes they still touch and why).
- Determinism on dirtied pages: a test that fills a region with garbage (build and drop a large collection full of nonzero data), then builds a fresh collection in the same space and checks equality, printing, hashing (as map keys), iteration order, map tombstones after removal and reinsertion, and stale pool ids (removed, retired, and pointing past the high-water mark) all behave exactly as on fresh pages.
- The whole existing suite passes; IR checks that `list {}` emits no memset over the element lanes.
- `nlc inspect memory`/`inspect contracts` unchanged in meaning; report peak pages touched for the probes.
- Report: docs/tasks/T23-report.md.

## Corrections from Sol's review (docs/reviews/sol-T23-r1.md), binding

Read the review for the evidence (file and line) behind each point. Decisions:

1. **Scope:** pool copies, resets and returns stay refused, and collections stay unhashable (not map keys), as today. Test only supported key types; test unreachable pool states (holes, retirement, ids past the high-water mark, full) with internal tests that seed the state directly, not as language programs.
2. **Maps:** initialise 8-byte buckets plus 1-byte flags per slot (9 bytes per slot, stated in `inspect memory`); hashes, keys and values stay lazy. Compaction and copies of `Ascii` keys visit only active records below the entry end (today's rebase visits every key slot and would read garbage). Rebuilding buckets may drop tombstones but must keep insertion order and behaviour. Tests: collision-heavy fill/remove/reinsert cycles that force compaction, nested values, copied Ascii keys, leaving the source scope.
3. **Pools:** reuse freed slots before taking a fresh one above the high-water mark; full only when no slot is reusable and the mark equals capacity; the mark only rises; a slot's metadata is written before it's published. Iteration snapshots and traversal stop at the mark captured when the loop starts. Pools that differ only in their high-water marks are still equal (equality compares occupancy, live generations and values, as now).
4. **Recursive rule:** initialisation and copies apply each element's own rule: an array or grid visits every element (all are live), and each element's collection fields follow the list/map/pool rules. Tests: arrays and grids of structs holding large empty lists, lists of lists, map and pool values holding lists. Flattening nested lanes stays the separate layout follow-up.
5. **One set of storage operations** shared by construction, copies, returns, T13's gather and scatter for collection elements (with write copy-back and cleanup on `?`), values under 4,096 bytes (whole stores today), equality and printing (whole operand loads today). Test both sides of 4,096 bytes and sparse nested fields through read and write calls, equality and printing.
6. **Option and Result paths:** `some`/`none`, `ok`/`err`, `?`, `??`, match bindings, unwrap and optional calls (direct and indirect, nested variants) initialise and read only the selected payload; today a `none` destination and propagated errors clear the whole result. Test success and failure with a large collection in either arm.
7. **Returns built in the caller's destination** only where it's provably safe (the output doesn't overlap an input and the local isn't observed after a partial write); otherwise copy live parts through scratch. Cover self-assignment, overlapping arguments, several returns, branch-local values and propagated errors; keep evaluation order, failed-write behaviour and correct `noalias`.
8. **Globals and constants:** update every layout, size and constant serializer together (the pool header, checker sizes, `llvm_constant` for generations and free lists) and the inspection totals. Globals keep the full startup claim and touch (DESIGN "Static allocation"): the live-only rule is for locals, the data stack and copies. Test empty and prepopulated compile-time globals, runtime initialisers and constant-to-local copies.
9. **Sort scratch** keeps its reservation accounting and tracks its own initialised range; never pass it to code that reads its count. Test empty and one-element lists, both algorithms around 16 elements, repeated sorts, sparse nested elements.
10. **Runtime and byte strings:** `fs.read`/`fs.list` set the count to zero on every failure with a valid buffer, publish counts after writing payloads, and clear no unused payload; byte-string construction stops clearing full capacity too. Test prefilled outputs, invalid paths, overflow, partial reads and sorted entries.
11. **Acceptance measurement:** state the platform, optimisation level, baseline (an empty program) and stack reservation; measure each case in a fresh process; the dirtied-page tests must show the address is actually reused. Add wrapped queue/ring copies with different heads, overwrite, empty and full, capacities 0 and 1, and mutation after copying. Report RSS separately from estimated pages touched. The million-slot map's target is about 9 MB of metadata, not 2 MB.
