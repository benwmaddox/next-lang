**Verdict: revise before implementation.** The process boundary and Rust AST target are sound. Exact structural equality is achievable, but the current postorder tables are not yet a complete, specified AST interchange format. Keep Rust the default through H1 validation.

1. **P1 — Specify every diagnostic span, not one span per node.** `ast.rs:1–80,200–386` includes operator, call, case, method, field, index, cast, range, effect-root, pattern-name and binding spans. The checker actually uses them (`checker.rs:2856,4938,9417,10593,11449`). Concrete trap: Rust preserves the entire grouped callee as `Call.call_span` (`parser.rs:1600–1626`); selfhost replaces its provisional Name without storing that span's end (`parser.nl:2201–2293`). Synthetic `default` has a zero-width expression span but a call span at `let` (`parser.rs:936–944`). **Recommendation:** require an AST-field-to-wire mapping, with explicit spans or documented lossless reconstruction for every field; add grouped/multiline callees, ignored bindings, effects and synthetic-node diagnostic cases.

2. **P1 — The writer does not “already hold” all promised values.** Strings/test names are decoded on output (`parse_output.nl:357`); type names and `expect` source are reconstructed. `parse_named_type` counts constant arguments and array capacities but discards those counts (`parser.nl:1144–1285`), although `TypeAst` stores separate vectors. A bare statement block also needs both `StmtKind::Block` and `Block` reconstructed from one syntax node. **Recommendation:** explicitly encode child roles/counts, synthesized names, decoded byte lengths, hex-origin flags and all optional/list fields. Preserve signed range bounds and unsigned four-limb magnitudes. T29's stored layout must never become the wire layout: serialize lengths/bytes and indexes, not structs or transient descriptors.

3. **P1 — Keep exact equality, clarify its domain.** H1:21 asks for trees even from syntax-error fixtures, which produce no tree. Most AST types currently lack `PartialEq`; matching dumps cannot substitute for comparing their hidden fields. **Recommendation:** compare ordered `Vec<Program>` plus file identities, every variant/value/span, on every syntactically valid package, including checker-invalid ones. Compare first diagnostic/status on syntax failures. Extend S1a's generated, mutation and boundary cases, not just repository fixtures. Permit parser-table improvements; do not normalize away span differences. This is differential AST equality, not merely a serializer round trip.

4. **P1 — Preserve driver semantics and checker visitation order.** `driver.rs:182–310` applies parse-only file/byte/node/work checks; compilation (`360–411`) does not apply that same policy and reports invalid UTF-8 differently. Selfhost currently follows parse-only policy (`source.nl:288`). The checker visits declaration categories in phases (`checker.rs:460,706`), rather than globally sorting declarations by position. **Recommendation:** explicitly reconcile the driver policies, preserving existing behavior or documenting/testing an intentional change. Rebuild per-file category vectors in original order and stable file IDs. Test multiple simultaneous checker errors across categories/files, earlier syntax versus later input failure, byte columns, and duplicate-declaration “first line” messages.

5. **P1 — Bootstrap must bypass frontend selection explicitly.** H1:15–16 creates recursion on an empty cache if building selfhost inherits `NLC_FRONTEND=selfhost`. The existing comparison test itself builds selfhost through `nlc` (`compiler/tests/selfhost.rs:21`). **Recommendation:** provide an internal Rust-only build path, independent of environment/defaults, and pin the S1a reference likewise. CLI flags override environment; define library selection and argument placement before `run`'s `--`. Test an empty cache under the selfhost environment. Locate selfhost sources independently of caller cwd.

6. **P1 — Version alone is an insufficient cache identity.** `compiler/Cargo.toml:3` remains `0.1.0` while T29 changes emitted text layouts. The build also reads runtime C and optimization settings (`driver.rs:1003–1099`). **Recommendation:** key by sorted source paths/content, `package.toml`, actual compiler build identity, runtime content, target, effective optimization/toolchain and wire version. Define cache location with `CARGO_TARGET_DIR`, serialize concurrent builders, and atomically publish only successful builds. Test each invalidation, missing/corrupt artifacts and simultaneous cold starts; use unique per-invocation tree files.

7. **P1 — Choose a streaming transport that exists.** H1:10 promises buffered file streaming, but `nl_fs_write` opens with `O_TRUNC` on every call (`runtime/nl_runtime.c:1697`). Rooted Fs also rejects absolute paths; existing language fixtures pass absolute package paths (`compiler/tests/language.rs:33`). **Recommendation:** prefer binary stdout redirected by Rust into a temporary file, or explicitly add a streaming-file prerequisite. Define child cwd/package-root mapping and symlink policy. Forward syntax stderr once with status 2; treat launch, signal, write and protocol failures as tool failures, never consumed partial trees.

8. **P1 — Bound validation before allocation and AST construction.** H1:11,23 mentions indexes/counts but not structurally invalid trees. **Recommendation:** check arithmetic overflow, section extents, tags/flags, child arities/roles, subtree partitioning, roots/file ownership, UTF-8 names versus raw byte strings, and span bounds. Cap allocations and depth/work before reconstruction; avoid recursive reader/drop stack exhaustion. Add malformed fixtures for these cases, including valid-size headers with impossible trees. Supply token metadata/source or resolved spans sufficient for decoding; file sizes alone cannot recover line/column positions. Define how selfhost `parse --tokens` obtains unchanged raw spellings without relying on Rust relexing.

9. **P2 — Measure the new path after T29.** S1a-2's 0.68/0.76-second figures include text dumps; its approximately 193-GB virtual reservation and 60-MiB RSS are different quantities. `parse_error_position` rescans source prefixes (`parse_output.nl:31`), which would become quadratic if reused per span. **Recommendation:** use a line-start index or linear pass; measure warm subprocess/write/read/reconstruction time and parent-plus-child memory, cold bootstrap separately, repeated small packages and the benchmark. Report wire size, RSS, reservation and post-T29 stack bounds. Reconcile PLAN's default switch with H1's recommendation-only acceptance before changing defaults.

10. **P2 — Make H2 a bounded declaration-index step.** PLAN:62 proposes name resolution/collection, but `Checker::run` interleaves registration with alias/type/global work. **Recommendation:** define an ordered top-level declaration index with stable file/node IDs and exact duplicate/error precedence, consumed by an explicit Rust checker seam. Compare that index and whole-suite behavior both ways. Leave lexical resolution, type elaboration, constant evaluation and typed output to separately specified steps.
