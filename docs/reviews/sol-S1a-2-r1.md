Verdict: **revise before implementation.** The design is implementable with the current language plus the declared T26 prerequisite, but its encoding and acceptance contract need corrections. Postorder storage, explicit traversal stacks and four-limb magnitudes are sound. Separate recursion-path measurements do not establish the required native-stack margin, and byte comparison covers exercised dump behavior, not every AST field. Source review only; no builds or compiler edits.

1. **High: the field encoding is incomplete.** The binding table (`selfhost-architecture.md:639`) assumes names are identifier spellings. `parser.rs:253` takes a decoded string for `Test`; `type_name_inner` assembles dotted names and synthesizes `()`, `fn` and `TextBytes`. Effect paths concatenate identifiers without intervening whitespace; `Expect.source` prepends exactly `expect ` to the expression slice (`parser.rs:869`). Neither is generally the raw construct's source range. `BytesLiteral` also needs decoded storage. **Recommendation:** specify each exceptional field's recipe, including synthetic `default`, and test dotted paths with whitespace, grouped/unit/function types, `Text bytes max`, escaped test names and unusual spacing after `expect`. Test-name `\xFF` becomes U+00FF through the lexer's `value`, whereas literal bytes retain FF (`lexer.rs:207`): these require different decoding modes.

2. **High: preserve the original lexer tokens.** `expect_type_gt` splits `>>` and `>>=` by splicing parser-owned tokens (`parser.rs:2302`); the driver passes a clone after preparing the original token dump (`driver.rs:261`). Doing that to S1a-1's shared package list would change dumps, shift stored token indexes and potentially alter token/work counts. **Recommendation:** use a parser cursor with virtual split pieces, or a separate mutable token representation with stable original references. Compare nested generics ending in both spellings, adjacent `=`, ordinary shifts and the resulting error columns.

3. **High: parsing must interleave with file loading.** Existing `load_and_lex` processes the entire package before returning (`selfhost/source.nl:205`). Appending a parser phase afterward would report a later file's lexical/read/byte error before an earlier file's syntax error. Rust parses and counts each file before reading the next (`driver.rs:212–308`). **Recommendation:** explicitly require per-file read/check/lex/token-check/parse/tree-count/package-limit processing, retaining successful data until final output. Add competing earlier-syntax/later-lexical and earlier-syntax/later-read-limit cases; the specified later-syntax/no-stdout test does not establish this order.

4. **High: one binary-chain test cannot validate the completed-tree walk.** `expression_nesting_exceeded` (`parser.rs:2405`) has Expr, Block and Type tasks. Blocks push the tail before statements; types visit AST argument groups rather than dump order, notably for `pool`; casts push value before type despite printing type first. Match patterns are skipped. **Recommendation:** document reconstruction of these roles from the encoding and add competing over-limit branches, statement-versus-tail cases, capacity/function-type expressions, root `print` versus ordinary roots, and a later syntax error competing with the walk. Preserve operator-token anchors separately from parenthesized node spans. A generic preorder scan cannot substitute for this walk.

5. **High: strengthen the native-stack acceptance proof.** The counters for expressions, casts, parentheses, blocks and types can coexist; malformed input can accumulate frames before the completed-tree check rejects it. Measuring each pure path at 1,000 with a 2× margin (`S1a-2-parser.md:11`) does not bound their combined live chain. T19's Rust measurements are not generated next-lang frame sizes. Also, T19 rejects large locals/results/temporaries across recursive cycles (`checker.rs:14890`), so local Rust-style argument or frame vectors cannot be ported literally. **Recommendation:** measure mixed successful and rejected inputs under supported optimization settings, account for the whole active chain, mark every function in each recursive cycle, and keep large scratch/frame lists caller-owned with per-invocation checkpoints. Move paths to explicit frames when the combined bound fails.

6. **Medium: define postorder construction, not just printing.** `postfix_call` replaces a `Name` with `Call`; a qualified-case call can replace previous arguments (`parser.rs:1600`). Struct literals replace their initial name too. Naively appending parents retains ghost nodes or breaks contiguous subtrees. **Recommendation:** specify delayed roots or checkpoint/replacement operations and assert subtree contiguity and reference counts. Include `f()`, indirect calls, `E.C(1)(2)`, shorthand fields and grouped postfix chains. Bound side-table and scratch slack too, so internal `Full` cannot preempt Rust's later syntax diagnostic.

7. **Medium: retain the limb plan, expand literal tests.** Four nonnegative 32-bit limbs suffice; decimal division intermediates fit signed `long`. But `integer` validates underscore placement before radix conversion (`parser.rs:2202`), ranges normalize negative zero (`:756`), and `stack_peak_comparison` multiplies magnitudes by byte units with a distinct overflow diagnostic (`:979`). **Recommendation:** add malformed separators/digits/prefixes, expression `-0` versus range `-0`, signed range overflow, and scaled `stack_peak` boundaries. For decoded output, test valid UTF-8 assembled from hex escapes, isolated invalid bytes, truncated sequences and escapes crossing the 1 MiB output boundary (`syntax_dump.rs:804`).

8. **High: edge N/N+1 acceptance is unreachable as written.** Every file is one tree, so edges = nodes − files. Both limits are 2,000,000; node overflow always wins before edge overflow (`syntax_dump.rs:113`, `driver.rs:283`). **Recommendation:** document this invariant instead of demanding an impossible black-box case; test edge accounting independently if desired. Test reachable node/work boundaries and paired failures: syntax before tree counting, per-file versus cumulative checks, and nodes before work. Run these with no dump flags too, since Rust still counts trees then.

9. **Medium: make comparison coverage and exceptions explicit.** The format document omits `Take` and omits `grow` from parameter modes, although the dumper emits both (`syntax_dump.rs:273`, `:516`). “Every field once” misses enum alternatives and absent/present children. Existing lexer-only directed sources often fail parsing before exercising their intended feature. The harness also accepts any status-3 tool-failure prefix (`compare-selfhost.sh:141`), conflicting with unconditional stderr equality. **Recommendation:** inventory coverage from `syntax_dump.rs`, require alternatives and parser-valid directed wrappers, wire `--parse` into the Cargo integration test, and state the narrow OS-message exception. Dumps omit fields such as `ByteString`'s hex-origin flag (`syntax_dump.rs:504`); preserve them for S2 separately.

10. **Language feasibility: mostly implementation work, with explicit workarounds.** T16/T23 supply raw Bytes and lazy collection storage; T17 sizes reservations; T24 supplies exit statuses and literal tables. T26 removes repeated exits from error helpers. Borrowed recursive tables already work (`tests/run/t19_recursion/main.nl:31`). Missing `while` and string-literal match patterns have bounded-loop and byte-comparison workarounds. T18's signed-long parsing cannot replace u128 limbs. Parser diagnostics interpolate arbitrarily long names (`parser.rs:733`), exceeding S1a-1's `Ascii max 160` message API; duplicate generics use a Rust HashSet. **Recommendation:** specify streamed token-bearing diagnostics and bounded source-slice hashing/scratch. Use concrete capacities where inference is awkward; no additional core language feature is required.
