**Verdict: revise before implementation.** Behavioural equality is the right acceptance for E1, and the scalar, non-recursive slice is a sensible first compiler. The spec needs closed subset boundaries, mandatory coverage, test execution semantics and a concrete bridge contract before Luna starts.

1. **P1 — Close the subset over its necessary language forms.** E1 does not explicitly include `()`, unary `-`, block tails or standalone blocks, although ordinary `fn main()`, negative integers and value-returning functions need them. Rust’s typed representation also needs `Never` for terminating expressions (`typed.rs:4–17`; `checker.rs:11066–11123`). “Compound assignment” could accidentally include unsupported shifts. **Recommendation:** enumerate allowed syntax, operators, parameter modes and annotations; include unit and internal never/fallthrough facts. Keep structs, collections, generics, capabilities as values and explicit recursion out. This is a practical minimum covering expressions, control flow and calls, slightly larger than a literal-printing compiler; avoid enlarging it beyond these closure requirements and basic tests.

2. **P1 — Unsupported must reject the entire package.** Rust registers declarations and checks every function and test, including unused functions and unreachable statements (`checker.rs:460–631,4444–4461`). Compiling only reachable supported nodes could silently drop an unsupported declaration, test or branch. Recursion also arises through ordinary calls without a `recursive` keyword. **Recommendation:** define a deterministic, exhaustive package eligibility pass over all files, node kinds, flags, type arguments and relevant manifest settings, before emitting an artifact. Mixed packages reject wholly, naming a construct and position. Separate unsupported syntax from ordinary errors such as unknown names/types; preserve Rust’s unmarked-cycle diagnostic at its whole-program phase. Reject marked recursion explicitly. Specify unsupported-versus-checker-error precedence for mixed packages.

3. **P1 — Acceptance currently permits rejecting everything.** E1 accepts any “not supported yet” rejection and merely reports counts. It also allows a selfhost-accepted invalid package to escape unless reference compilation success is checked explicitly. `language.rs:6–165` includes both executable and compiler-error fixtures. **Recommendation:** maintain independently classified must-build, must-diagnose and unsupported cases. Every directed supported case must succeed or reproduce its expected error; unsupported results there fail acceptance. Require reference acceptance before comparing executions; pin the oracle and bootstrap to `--frontend=rust`. Retain repository expected outputs as a second oracle. Add generated valid and multi-error subset packages, nested feature combinations and boundary cases, at default `-O1` and `NLC_OPT_LEVEL=3` as PLAN’s S3 requires. Compare raw output bytes under identical cwd/arguments/environment; document any fixture-only path normalization (`language.rs:187–217`). Resource limits, tool failures, signals and timeouts must never count as unsupported.

4. **P1 — Exact first errors are achievable within agreed input limits, but a linear postorder check is insufficient.** `Checker::run` registers signatures/tests, checks the entry, then bodies and tests, then analyses (`checker.rs:500–631`). Moreover, `check_operand_pair` checks the right operand first when only the left is an unsuffixed literal (`11955–12000`): `print(2147483648 + missing)` diagnoses `missing` before literal overflow. Loop inference scans body uses before checking bounds (`5551–5602`). The research’s linear walk is therefore guidance, not a sufficient algorithm. **Recommendation:** document the subset’s actual phase/category/file/function/expression ordering; use explicit enter/resume tasks carrying expected types and scope state. Test competing signature/body/test errors, operand reversals and loop-inference errors. Match diagnostic bytes, filename, byte column, line and status 2; tool failures remain status 3 (`main.rs:160–169`).

5. **P1 — Turn runtime equality into a semantic checklist.** `emit.rs:21579–21825` checks signed add/subtract/multiply/negate, guards division by zero and minimum-value division by `-1`, but makes minimum-value **remainder** by `-1` zero. Guards use operator spans, including compound assignments. Inclusive loops avoid incrementing past the final maximum (`15830–15905`). `nl_fail` flushes output and exits 1, or 70 in test mode (`nl_runtime.c:905–935`). **Recommendation:** direct fixtures must cover both widths, negative literals versus dynamic negation, both zero divisors, division/remainder signs, short-circuit suppression, left-to-right runtime evaluation, bounds evaluated once, empty/reversed/extreme ranges, nested loop exits and returns. Require exact filename/line/column/message/newline and prior printed output, not just matching arithmetic results.

6. **P1 — Tests need an explicit supported mode and runner.** E1 promises per-test results but lists neither `test` nor `expect`, and only specifies `build`. Rust checks tests during ordinary builds, permits test-only packages without main, and launches each test separately with `NLC_TEST_INDEX` (`driver.rs:733–740,813–893`). The wrapper calls `nl_set_test_mode`; expectations return 1 immediately; runtime failures return 70 (`emit.rs:850–895,16227–16343`). **Recommendation:** include parameterless scalar tests and bool/comparison expectations, with decoded names and preserved expectation source. Add a test compilation mode, ordered test metadata and a comparison runner reproducing Rust’s child isolation, status lines, forwarded output and summary. Ordinary executables still run main only. Reject Env/Result/stack-peak tests explicitly; require passing, failing, runtime-failing and empty-test fixtures.

7. **P1 — Specify `link-ir` as a driver seam, not an approximate clang command.** Today `run_clang` compiles IR **and runtime C**, uses `-O1`/`-O3`, optionally `-DNLC_TEST_BUILD=1`, the stack-mode define and `-fstack-size-section`; it supplies no explicit target triple (`driver.rs:1344–1487`). T19 additionally needs `CompileOutput`’s call graph and recursive flags, not just IR comments. T17 reservations are computed before emission (`emit.rs:2979–3087`). **Recommendation:** share toolchain invocation and error handling, fix/document the host target, and carry test/ABI metadata explicitly. Emit the scalar entry’s helper-margin/page-rounded reservation. Skip T19 probing only under the checked acyclic restriction; reject recursion markers the bridge cannot patch. Preserve a metadata seam for probe/read/patch/rebuild-to-stability and future T17 native-frame checks. Respect PLAN’s offset support-or-fail-closed rule even though E1 allocates no target regions.

8. **P1 — Scalar programs still need package and entry semantics.** `print` requires manifest `out` permission (`checker.rs:9881–9883`); entry validation precedes body checking (`3611–3641`). The generated C `main` creates context/environment, registers source filenames and destroys the context, which flushes buffered printing (`emit.rs:716–850`; `nl_runtime.c:440–445`). **Recommendation:** explicitly consume H1b’s agreed file/input policy and manifest defaults, validate supported configuration and main’s signature, preserve sorted file identities and escaping, and reproduce startup/cleanup. “No data-stack regions” does not justify omitting buffered-output cleanup or silently ignoring denied capabilities.

9. **P2 — Specify reusable checker tables now.** Parser nodes already carry subtree sizes and spans (`parser.nl:223–235,586–689`); Rust uses stable type IDs (`typed.rs:4–36`). **Recommendation:** keep immutable syntax plus node-indexed typed facts, with separate ordered function/signature/parameter, scope/binding/local, call-edge and type tables. Represent unit/never/primitives as type IDs in an extensible type table; keep literal magnitudes in four limbs until contextual range checking finishes. Use source slices or interned name IDs, indexed line starts and explicit diagnostic anchors. Caller-owned work/value stacks must retain scope and contextual-type state across nested checks. Avoid copying whole parser tables or repeatedly rescanning children; defer parallel waves and a public typed interchange format beyond E1.

10. **P2 — Give emission an owned buffer and control-flow contract.** Postorder syntax does not directly encode short-circuit branches, joins or terminators. `collect_children` overwrites shared scratch (`parser.nl:2998–3019`), so nested visitors cannot retain it casually. **Recommendation:** lower typed facts through explicit emission frames; use function-local value/block IDs, entry allocas, terminator tracking and valid phi predecessors. Centralize type/ABI lowering, failure kinds and runtime declarations for E2–E4. Append into caller-owned `Bytes` builders with checked capacity, deterministic sections and linear formatting. Start with one module. Define output-path rooting and write failure handling: Fs writes truncate each time (`nl_runtime.c:2227–2235`), so writing successive buffer chunks is not streaming. Publish no usable partial IR after rejection.

11. **P2 — Budget the compiler itself, separately from its scalar output.** `main.nl:63–81` already owns large source/token/parser buffers; `limits.nl` permits millions of records, and the parser’s manifest budgets 7800 KiB of recursion. New typed tables, work stacks and IR buffers coexist with these. **Recommendation:** specify capacities, checked exhaustion diagnostics, caller-owned scratch and phase lifetimes before adding tables. Measure computed versus observed compiler stack peaks, reservation and RSS separately, plus bootstrap, checking, emission and clang timings. Generate a valid, uniquely named subset benchmark: the existing generator repeats declarations and unresolved filler (`scripts/gen-bench-corpus.sh`). E1 is built by pinned Rust stage 0; self-compilation and stage-2/3 stability belong later, as research §5.4 states.
