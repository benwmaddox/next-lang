**Verdict: revise before implementation.** The next-lang core, direct Linux syscalls, embedded sources and offset-based I/O follow DESIGN.md’s single stack-and-arena approach. The temporary scalar dialect and C-shaped hook ABI are reasonable bootstrap choices; C calling conventions do not require libc. However, the libc-memory exception contradicts the decided rule, and pinning, startup and file-writer contracts need corrections.

1. **P1 — Direct-argument syntax does not establish pinning.** `core-library.md:648` accepts `sys.write(fd, sys.stack_addr(ctx, at), compute_count())`. E1 requires left-to-right argument evaluation (`E1-selfhost-end-to-end-slice.md`, runtime checklist), so `compute_count()` can grow the stack after address derivation. Similarly, `sys.stack_store8(ctx, at, compute_value())` needs careful lowering. **Recommendation:** evaluate all ordinary arguments into offsets/scalars first, then derive every address immediately before the operation. Alternatively, reject potentially growing remaining expressions. Test forced relocation during argument evaluation. Foreign buffer callbacks also require an enforced pin that refuses or defers growth during re-entry. Keep asynchronous operations unavailable until completion pins or the measured pinned-arena option, including cancellation cleanup, exists.

2. **P1 — Resolve the memory-function attribute contradiction and strengthen verification.** Lines 75/302 restrict `"no-builtins"` to memory functions/helpers; lines 533/683 prescribe it everywhere. On clang/opt 18.1.3, my two-function experiment retained the call at both optimization levels; `alwaysinline` bypassed that protection. This matches LLVM’s [compatibility rules](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.3/llvm/include/llvm/Analysis/TargetLibraryInfo.h) and [always-inline exception](https://github.com/llvm/llvm-project/blob/llvmorg-18.1.3/llvm/lib/Analysis/InlineCost.cpp). Simple protected copy/fill loops produced no libcalls on either target, but the attribute is not a backend-wide prohibition. **Recommendation:** choose one policy, forbid memory intrinsics in the entire memory-helper closure, and inspect transitive call cycles, clones and tail branches: the proposed direct-call scan misses `memcpy → helper → memcpy`. Gate LTO on equivalent post-link checks; preserve attributes and assembly-referenced entry roots through internalization.

3. **P1 — The libc variant introduces the dependency DESIGN forbids.** Lines 267/685 explicitly delegate the core’s LLVM memory calls to libc; DESIGN.md:159 says the core still never calls libc. External libraries requiring libc are permitted, but this additional core dependency is a policy change. Also, flushing core buffers *before* foreign `printf` (risk 5) cannot flush libc’s newly buffered output: subsequent core output can overtake it. **Recommendation:** specify self-contained memory lowering/private implementations in this variant, with symbol visibility and static-archive behavior tested. Require output bindings to finish/flush their own output before returning. An exception needs Ben’s recorded design decision.

4. **P1 — `main`’s environment need not precede auxv.** Line 264 assumes libc passes the initial-stack environment. [glibc calls main with `__environ`](https://github.com/bminor/glibc/blob/glibc-2.39/sysdeps/nptl/libc_start_call_main.h); a foreign constructor can replace that array through `setenv` before main. Scanning beyond its terminator then reads unrelated memory. **Recommendation:** give auxv/page-size discovery a separately specified startup path for this variant. Keep current environment lookup separate from initial-stack metadata, and test a constructor that changes the environment. Do not silently use 4096 on arm64, which supports larger kernel pages.

5. **P2 — Close the bootstrap dialect and its retirement schedule.** Summary decision 1 makes casts core-only, while line 71 makes them ordinary; line 81 promises globals in E2 although PLAN’s E2 lists structs/enums/Result, not globals. `sys.load64` returns `long`, while `sys.from_raw` is documented as mmap-only, leaving pointer fields/environment traversal underspecified without null-base address arithmetic. **Recommendation:** enumerate the exact accepted forms, pointer loads/stores, intrinsic signatures and checked-arithmetic behavior. Schedule globals/constant data explicitly, retaining the state block until supported. Compare ordinary feature additions against Rust; retire each bootstrap mechanism in its owning E-task. Embedding/hash/staleness checks are appropriate; apply input-size budgets to the embedded unit separately from user input.

6. **P2 — Tie ABI migration to actual prerequisites.** Line 391 deletes the third C leg after E2; risk 3 delays replacing the hook ABI until Rust freezes, which PLAN places after whole-suite coverage. These are different milestones. **Recommendation:** keep the fixed hook table while comparison requires it, but schedule context passing before jobs/concurrent output and region-using core functions. Keep standard memory-function signatures independent of hidden job parameters. State which checks replace the third leg when it is removed.

7. **P2 — Seal all privilege entry points.** Embedded-unit identity and separate user checking (178–181, 378–380) prevent package-name/path spoofing; mangling prevents ordinary hook-name collisions. They do not themselves specify symbol visibility, inferred privileged types or the proposed core-test command. **Recommendation:** make non-hook core symbols private, exclude core declarations from user name resolution/function values, and reject privileged types through aliases/inference too. Core-test must select embedded tests only, never accept arbitrary privileged source paths. Foreign bindings remain explicitly trusted; reserve internal symbols there rather than implying `sys` restrictions sandbox foreign code.

8. **P1 — Atomic-write errors must identify the commit state.** Line 607 says `Other(errno)` tells the caller replacement already happened, but identical errno can arise before rename. A directory-close failure after successful directory fsync also does not undo established durability. Line 606 promises removal while ignoring unlink failure. **Recommendation:** distinguish pre-commit failure from committed-but-durability-uncertain failure; document possible leftover temporaries and always close descriptors. Inject failures at every step. Use bounded temporary basenames independent of the target: adding a suffix to a valid maximum-length name exceeds `NAME_MAX`. Reject automatic deletion based solely on filename/PID; neither proves ownership, especially across PID namespaces.

9. **P1 — A streaming writer needs resource and borrowing semantics.** Lines 621–626 store a live descriptor and borrowed buffer offset in an ordinary value, then promise mandatory close and job cleanup. Handling each method’s `Result` does not prevent copying the writer, double-close, buffer reuse or escape beyond the buffer’s scope. **Recommendation:** specify unique writer ownership, exclusive buffer borrowing, moves/parameters, and cleanup on early return/`?`, failure and cancellation. Register cleanup without per-operation heap allocation. Separate abort from commit so rejected builds never publish; prove these rules with control-flow and lifetime fixtures before switching compiler emission to streaming.

10. **P2 — The file checklist omits observable reference behavior.** The new size precheck (581) changes reads of files that shrink after stat; `nl_fs_read_string` currently reads/probes without stat (1900–1958). More concretely, `nl_fs_list_with_extension` follows permitted symlinks through `nl_entry_kind_beneath` (1671–1691, 2207), whereas ordinary listing uses no-follow classification. Applying line 588 uniformly changes returned kinds. **Recommendation:** enumerate every Fs overload/helper, including extension filtering and join; retain their distinct semantics or change both runtimes in the same task. Treat the size hint as advisory unless the early-rejection behavior is explicitly adopted.

11. **P2 — Kernel failure diagnostics must preserve the error contract.** Risk 9 proposes named failures for `ENOSYS`/`EPERM`, but the specified API maps these to `Other(38)`/`NoPermission`; `EPERM` alone cannot identify seccomp. **Recommendation:** state the supported kernel baseline, preserve recoverable IoError results, and attach syscall context at the reporting boundary consistently in both runtimes. Keep the refusal to fall back to unchecked `openat`.

12. **P2 — Use an explicit assembly boundary for native-stack switching.** Lines 289–290 hide a call and stack-pointer replacement inside inline asm. Caller-saved clobbers alone do not describe red-zone use, alignment, unwinding and preservation of the original stack. **Recommendation:** use compiler-emitted assembly stubs with an explicit ABI and CFI for both returning and nonreturning switches; test guard probing, callee-saved registers and return-to-libc. This remains deferred beyond E1c.

The syscall numbers, x86-64 register/clobber choices and arm64 `x8`/`x0–x5` convention check out; [Linux restores arm64 PSTATE](https://github.com/torvalds/linux/blob/v6.6/arch/arm64/kernel/entry.S), so an extra condition-code clobber is unnecessary. The shared kernel sigaction layout is correct for these targets. Use the exact `-4095..=-1` error predicate consistently. The shown x86-64 entry linked and ran at `-O1`/`-O3`, producing `EXEC` binaries with no undefined symbols. Static non-PIE and deferred ASLR are explicit choices; also test absence of interpreter/needed-library entries. Arm64 was cross-compiled, not executed. Output/test/failure hooks match the inspected C and emitter shapes; `/dev/full` tests failure, not partial-write recovery, which needs deterministic injection.
