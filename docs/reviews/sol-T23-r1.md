Verdict: **revise before implementation.** The intended optimization is implementable, but T23 needs tighter representation contracts, explicit scope limits and stronger acceptance cases. Its universal return requirement and collection-key hashing tests exceed what the current implementation supports. Reviewed DESIGN's collections/maps/pools, “Static allocation” and “Where data lives”, the architecture review, research §2.3, and current emitter/runtime sources. No builds or probes were run; compiler sources are being edited concurrently.

1. **High: pool copies/resets and collection hashing need scope decisions.** `checker.rs:3822,3979,2932` reject pool copies, replacement/reset and returns; `type_is_hashable` (`:2180`) excludes collections, including structs containing them. T23's copy/reset and “hashing (as map keys)” acceptance cannot run as ordinary language tests. **Recommendation:** retain these restrictions, test supported key types, and use internal tests for unreachable pool states. If enabling these features is intended, specify owner/lifetime rules and hashing semantics separately. Preserving generations during reset also requires invalidating formerly live ids; merely retaining their counters is insufficient.

2. **High: map compaction and Ascii key copying must be explicit.** Lookup reads buckets first (`emit.rs:4258`); iteration uses entry-end, not live count (`:9597`). `emit_map_compact` (`:4377`) moves active records and rebuilds all buckets when insertion-order storage fills. More dangerously, `emit_rebase_growing_payload` (`:7880`) visits every Ascii key slot: lazy initialization would expose garbage pointers/lengths. **Recommendation:** choose 8-byte buckets plus 1-byte flags per capacity slot (9N bytes), leave hashes/payloads lazy, and bound key copying by active records below entry-end. Test collision-heavy fill/remove/reinsert cycles forcing compaction, nested values, copied Ascii keys and source-scope exit. Clarify whether rebuilding may discard tombstones while preserving order and behavior.

3. **High: define the pool state machine and comparison semantics.** Current add consumes the prefilled free stack (`emit.rs:5071`); removal increments generations or retires slots (`:5196`). Iteration first snapshots occupancy across capacity (`:8669`), independently of its body. Equality compares occupancy and live generations/values, ignoring vacant history (`:10911`; `const_eval.rs:3525`). **Recommendation:** specify reuse-before-virgin allocation, full iff no reusable slot and high-water equals capacity, monotonic high-water, and metadata initialization before publishing a slot. Bound snapshot creation and traversal by the captured high-water mark. Different high-water marks alone must not make pools unequal. Test Full, holes, reuse order, retirement and ids beyond the mark using seeded internal state.

4. **High: “arrays/grids stay fully initialized” conflicts with recursive liveness.** `Fill` clears its whole destination and loads/stores whole elements (`emit.rs:8072`); collection lanes currently hold nested collections inline (`:1555`), rather than implementing DESIGN's eventual complete flattening. An array of empty lists has every outer element live, but its inner capacities remain unused. **Recommendation:** define initialization/copy recursively: visit every array/grid element, then apply that element's representation rule. Require arrays/grids of structs containing large empty lists, lists of lists, and map/pool values containing lists. Explicitly leave the separate flattening task out of scope.

5. **High: include T13's gathers, scatters and small aggregates.** `emit_gather_collection_element` and `emit_scatter_collection_element` move full field sizes (`emit.rs:3767,3823`); call preparation/copyback uses them (`:6197,6268`). `emit_expr_to` still stores whole values below the 4,096-byte threshold (`:7914`), while printing/equality materialize whole operands (`:9439,10834`). **Recommendation:** share recursive storage operations across these paths, preserving write-copyback and cleanup on `?`. Test both sides of 4,096 bytes and nested sparse fields passed through read/write calls, equality and printing. Removing only large memsets is insufficient.

6. **High: enumerate Option/Result control-flow paths.** Generic enum construction is covered in prose, but optional calls clear even a `none` destination (`emit.rs:9947`), propagated errors clear the entire result (`:10112,10225`), and successful `try` uses the full-storage copy helper (`:10292,7719`). **Recommendation:** explicitly include `some`/`none`, `ok`/`err`, `?`, `??`, match bindings, unwrap and optional calls, including indirect calls and nested variants. Initialize/read only the selected payload. Test both success and failure with a large collection in either Result arm.

7. **High: universal construction in the caller needs a safety condition.** Caller destinations already exist (`emit.rs:3035`), but ordinary returned locals still allocate separately; T14's builder recognition is specialized (`:1760`). Redirecting every local can expose partial writes when output overlaps an input or the local remains observable. **Recommendation:** require direct construction for a stated provably safe case; permit recursive live-only copying through scratch otherwise. Cover self-assignment, overlapping arguments, multiple returns, branch-local builders and propagated errors. Preserve evaluation order, failed-write behavior and valid alias annotations.

8. **High: update global/constant layout producers too.** Pools have five metadata/lane-prefix fields today (`emit.rs:313`); sizes also appear in `checker.rs:2381`, and `llvm_constant` emits generations/free lists (`emit.rs:2323`). **Recommendation:** update every layout/size/constant serializer and inspection calculation together. Test empty and prepopulated compile-time globals, runtime initializers and constant-to-local copies. Keep globals' full startup claim/touch policy (`nl_runtime.c:496`; DESIGN “Static allocation”); the live-only rule needs this explicit exception. Inspection meanings remain stable, but byte totals may change.

9. **Medium: sort scratch has its own validity rule.** `emit_sort` reserves collection-sized scratch, writes selected elements, and copies only through count; it does not initialize a list scratch header (`emit.rs:11133,11421`). **Recommendation:** preserve reservation accounting, track scratch's initialized range independently, and never feed it to a helper that reads its count. Test empty/singleton lists, both sorting algorithms around count 16, repeated sorts and nested sparse elements with a supported comparator.

10. **Medium: specify runtime failure observability.** `nl_fs_read` clears on entry/path failure/partial failure; `nl_fs_list` writes nested name counts and separate kind lanes (`nl_runtime.c:940–1069`). **Recommendation:** require count zero on every valid-buffer failure, publish successful counts after payload writes, and clear no unused payload. If partial writes need clearing, restrict it to initialized bytes. Test prefilled outputs, invalid paths, overflow and partial reads, plus sorted directory entries. Include byte-string construction, which independently clears full capacity (`emit.rs:5296`).

11. **Medium: separate memory and dirty-storage acceptance.** The under-2-MB list delta is plausible on the stated Linux setup, not a portable absolute guarantee. The proposed million-slot map needs approximately 9 MB metadata; sparse pools need only headers and initialized slots. **Recommendation:** fix platform, optimization flags, baseline, observable outputs and stack reservation. Measure each case in a fresh process; dirtying full capacity permanently contaminates peak RSS. Prove actual address reuse in determinism tests. Add wrapped queue/ring copies with different heads, overwrite, empty/full, capacities 0/1, and post-copy mutation. Report RSS separately from instrumented/estimated pages touched; `/usr/bin/time` alone cannot identify those pages.
