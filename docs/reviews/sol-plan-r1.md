# Plan / T01 review

## 1. Milestone order and rework

- **M2 promises acceptance cases whose dependencies land in M3 or later.** DESIGN step 1 includes text size classes, Ascii/Text parameter modes, large-local scratch, iteration cleanup, suspension/view checks, invariants, and startup admission. Split M2 into fixed-size state/ids and a later payload/lifetime slice; enumerate the acceptance cases each owns. Otherwise “all step 1 cases” silently pulls M3 and scheduler work forward.
- **M1’s refinement contract is unsettled.** PLAN says checked-on-store; DESIGN also says unproved internal refinements are build errors requiring `check`, and describes failed field writes returning errors. Decide assignment, argument, return, and field-write behavior before M1. Separate runtime enforcement from M4 proof/check elimination, with shared boundary tests; do not implement three incompatible failure conventions.
- **Give M0 a small typed representation before LLVM emission.** Preserve source spans, resolved symbols, call edges, lexical scopes and explicit control-flow exits. Centralize call-signature lowering and failure emission. Parsing directly into LLVM strings, or hardcoding scalar signatures throughout, will force M2/M3 to reconstruct lifetimes, cleanup edges and hidden context/destination arguments. No optimizer or full stack ABI is needed now.
- **Keep failures structured.** Carry a failure kind and source span to a reporting boundary; do not scatter formatted messages or process exits through generated functions. Preserve call-site spans for later refinement/effect diagnostics. Mark `print` as observable builtin metadata now so M1 constant evaluation cannot execute it as a pure helper.

## 2. T01 ambiguities: proposed answers

- **Grammar/unit:** specify newline termination, multiline continuation, optional semicolons, precedence, shadowing and duplicate declarations before implementation. My default: newline ends a complete statement outside parentheses; semicolons optional; lexical shadowing allowed, same-scope duplicates rejected. Omitted return type means `()`; `main` must be `fn main()` returning unit; value-returning functions must produce a value on every reachable path.
- **Evaluation:** operands and arguments run left-to-right; `&&`/`||` short-circuit. Capture each `expect a == b` operand once, then compare and report captured values. A failed expectation ends that test.
- **Ranges:** evaluate bounds once, ascending only; reversed bounds are empty. Inclusive maximum endpoints must terminate without increment overflow, including through `continue`. Support DESIGN’s explicit `for i: long`; declared bounds constrain the counter, otherwise use body context, defaulting to `int`; conflicting constraints require a cast.
- **Integer edges:** accept signed minimum literals without first overflowing their positive magnitude. Specify arithmetic right shift; left shift discards high bits after checking the count. For `%`, reject zero but define `MIN % -1` as zero, guarding before LLVM remainder. Add boundary tests alongside checked unary negation and division.
- **Harness/CLI:** `expected.txt` cannot unambiguously encode exact output plus exit status. Use separate stdout, stderr and status expectations, including compile-fail fixtures. Normalize only temporary/root paths. Test order is filename then source order; reject duplicate test names. Compile once and launch a child per test initially so runtime failure isolation needs no unwinding machinery. Pin exact failure formatting, newline behavior for `print`, and compiler/tool failure exit codes.

## 3. Split T01

T01 combines a compiler frontend, checked backend, control-flow lowering, native driver and test framework. Split into independently passing slices: (a) workspace/driver, spans, functions, scalar literals, calls and print; (b) bindings, type checking, checked arithmetic/casts and negative fixtures; (c) block values, branches, ranges and cleanup-aware exits; (d) test discovery, expectation diagnostics and failure isolation. Each slice needs its own end-to-end acceptance commands; the report should not be the first place semantic choices become reviewable.
