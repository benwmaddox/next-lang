# Round 17 review

## 1. Factual corrections

At `DESIGN.md:614`, say v3 adds to v2 the [x86-64 feature-spec entries](https://gitlab.com/x86-psABIs/x86-64-ABI/-/blob/master/x86-64-ABI/low-level-sys-info.tex): AVX (256-bit floating-point vectors), AVX2 (256-bit integer vectors), BMI1/2 (bit-manipulation instructions), F16C (16-bit/32-bit float conversion), FMA (fused multiply-add), LZCNT (leading-zero count), MOVBE (byte swap on load/store), and OSXSAVE (OS support for saving extended registers). A 256-bit vector processes eight 32-bit values or four 64-bit values together. Thus eight-wide game arithmetic applies to `Float32`, not default 64-bit `Float`; it is capacity, not a speed promise. Suitable bitstream, bitmap, or text code may use BMI or wider vectors, but the level alone does not speed up DEFLATE, slot scans, or UTF-8 validation. F16C converts half-floats; it does not do half-float arithmetic. [Intel AVX/AVX2 overview](https://www.intel.com/content/www/us/en/support/articles/000005779/processors.html), [Haswell feature notes](https://www.intel.com/content/dam/develop/external/us/en/documents/how-to-detect-new-instruction-support-in-the-4th-generation-intel-core-processor-family.pdf).

Delete the broad prevalence dates and “one in 20” estimate unless backed by a dated sample and method. Google Cloud currently documents N1 VMs on Sandy Bridge and Ivy Bridge as well as Haswell, and says AVX2 starts at Haswell, contradicting “all servers and clouds since about 2014.” Steam reports separate CPU-feature percentages, not the intersection of every v3 requirement, so its survey cannot establish that fraction. [Google Cloud CPU platforms](https://docs.cloud.google.com/compute/docs/cpu-platforms), [Steam survey](https://store.steampowered.com/hwsurvey/T?platform=pc).

## 2. Contradictions and exact fixes

Define the *minimum target* as the lowest CPU level the whole artifact may require: v3 by default, lowered by a build flag or manifest subject to the platform floor. At `:621`, replace “For programs built below v3” with “For any selected minimum target,” preserving v4 specialization for default builds. A function *clone* is a separately compiled copy: its fallback clone uses the selected minimum; v3/v4 clones add faster paths and cannot let a v3-default artifact run on v2. Say `fma(a,b,c)` has the same one-rounding result at every level, using hardware FMA or an equivalent software fallback. Record an older-level rebuild as a distinct build identity; cross-build replay is best effort. Forced clone selection must still check that the machine supports it.

## 3. Practical effects and refusal

Continuous-integration (CI) runners, older laptops, virtual machines (VMs), and Android x86-64 emulators expose different feature sets. Default binaries refuse wherever v3 is unavailable, even if compilation succeeded elsewhere. QEMU’s default `qemu64` is below v3; Android’s x86-64 binary interface has a v2 floor, so reject v1 there. Updated Windows 11 Prism emulation supports AVX/AVX2, BMI, FMA, and F16C; older versions may not. Check the full feature set exposed to the emulated process. Keep the feature check, function selector, refusal path, and anything that can run before the check (including dependency initialization) compiled for the platform’s *safe-start baseline* (x86-64 v1, Android x86-64 v2), not the selected minimum; prevent link-time optimization (cross-module optimization, LTO) from introducing higher-level instructions there. [QEMU CPU models](https://www.qemu.org/docs/master/system/qemu-cpu-models.html), [Android ABIs](https://developer.android.com/ndk/guides/abis), [Microsoft Windows 11 release notes](https://support.microsoft.com/en-au/servicing/os/windows-11/2025/12/december-1-2025-kb5070311-os-builds-26200-7309-and-26100-7309-preview).

Specify precedence as build flag over manifest over v3 default. Refusal should name the required level and missing CPU or OS register-state features, then direct users to obtain or rebuild the whole artifact, runtime, and dependencies with `build --target-level x86-64-v2` or `build --target-level x86-64`, where allowed; a run-time flag must not bypass the check. Validate refusal with guest features masked and OS vector-state unavailable. The compiler/bootstrap must itself run on older hosts for the lower-level build to help.
