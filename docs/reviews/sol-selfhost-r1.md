# Sol: self-hosting assessment, round 1

Ben: the decided model can express a compiler, subject to unresolved ID typing and library contracts. Today's implemented language cannot. Keep Rust through validation; consider self-hosting afterward. Self-hosting means writing the compiler in the language it compiles. It is an engineering test, not evidence that the language is correct or useful elsewhere.

The current Rust compiler uses growable vectors and strings, boxed expression trees, hash maps, and a driver that invokes clang. A rewrite would change its data structures, not just its syntax. LLVM would still produce machine code, and the C runtime could remain C.

A pool holds bounded, stable slots; a typed ID names a slot and its owner. A capability is an explicit permission value.

**What the compiler would look like**

- **Token stream:** tokens are the words, numbers and punctuation recognized in source. Use a bounded `list<Token, N>` per file, with kind and byte-offset/length into retained source. Avoid copying each spelling. A streaming lexer can reduce token storage, but retained trees and diagnostic excerpts still need source access. Declare `long` offsets; conversions to narrower fields must be explicit and checked.
- **Syntax tree:** the nested structure of expressions and declarations becomes an enum of node kinds in a pool, with typed child IDs instead of pointers. Store variable-length child sequences in a separate bounded list and give nodes ranges into it; a maximum-size child list inside every node multiplies memory waste. Build per file, then freeze into one scoped batch. Later passes put resolutions and inferred types in separate maps; frozen rows cannot be patched. Recursive parsing requires `recursive`, retaining fixed-size IDs rather than growing text across recursive calls, and a native-stack budget. An explicit bounded traversal stack is another option.
- **Symbols and interning:** a symbol table maps names to declarations. Interning stores each distinct spelling once and uses an ID thereafter. Use a bounded map plus spelling storage, then maps from spelling IDs to declaration IDs. Hash collisions still require spelling comparison. A job-local interner is straightforward; parallel interners need a merge and ID translation, or a serial interning phase. One shared writer risks becoming the bottleneck.
- **Type representations:** types such as “function taking two integers” are enum records in a local type pool, linked by IDs. Cycles are representable without recursive storage. Keep caches and unfinished types mutable and local; freeze completed representations when sharing helps. Generic expansion—making concrete copies for different type arguments—needs its own count and work limits, beyond source size.
- **Work list:** pending name-resolution, type-checking and call-graph tasks fit a bounded queue/list with a visited set. These analyses revisit dependencies until facts stop changing. Bound both storage and total processing steps; a finite queue does not guarantee termination. End views before removing entries. Named helper functions with explicit context replace closures, which would otherwise capture surrounding variables.
- **Diagnostics:** bounded records hold file IDs, source spans (locations), error codes, related locations and suggestions. Format when reporting; cap retained errors and report the omitted count. Unlike logsum's `untracked` paths, missing symbols or nodes must stop compilation. Keep compiler state local and pass it explicitly; large globals pay their full claim at startup and restrict worker placement.
- **Large output:** emit LLVM's textual intermediate representation (IR) using bounded buffers and append mode, freeing temporary formatting each iteration. Prefer flushing chunks over one project-sized string. A pure parallel emitter can produce bounded per-file chunks, then a coordinator writes them in deterministic order. No implicit conversions means explicit numeric formatting and casts throughout.
- **Files and processes:** pass filesystem capabilities from `main`, as logsum proposes; read bounded source bytes and write temporary IR/object files. Launch clang with an argument list, capture bounded diagnostics, inspect exit status and clean up temporary files on failure. Those process facilities are not specified yet.
- **Parallel work:** read files through I/O jobs or before parsing; effect-free `parallel for` bodies cannot read files. Move one builder into each parser chunk, join, freeze, then check through read-only views with per-job caches. Cross-file dependency cycles need coordination between phases; arbitrary shared mutable checking caches are unavailable. Scoped parallel blocks are allowed despite the ban on stored closures.

**Missing specifications and milestone placement**

Distinguish missing implementation from missing design: pools, recursion, frozen batches and function values are already decisions.

- **M1:** finish generic constraints, equality/hash requirements and error propagation. Automatic error conversion is optional; logsum's explicit helper suffices. Specify checked integer-literal accumulation without relying on Rust's `u128`.
- **M2/M3:** specify how reusable `Node`/`Type` definitions name IDs belonging to a particular local pool or batch, including self-links, helper parameters, copies and returns. Raw integer links would evade the intended guarantee. Schedule maps/sets/queues, hashing and sorting explicitly; they currently sit in “Later.” Specify byte slicing, UTF-8 validation, numeric parsing/formatting and bounded writers alongside M3 text support.
- **M4 onward, effects step 5:** define a process capability and its effect; the closed list currently has none. Specify file handles, partial reads/writes, paths, temporary files, rename, cleanup on cancellation, process arguments/status and bounded stdout/stderr capture. Examples suggest APIs, not complete contracts. A small C binding can bridge these initially.
- **Builders/parallel step 6:** finish builder handoff, batch-dependent helper types, aggregate budgets and lifetime checks. Test IDs crossing workers and being rejected across batches. Full adoption waits for step 7's four-program validation; no numbered milestone beyond M3 is fixed yet.

**Bounds for variable projects**

Declare ceilings for files, individual/total source bytes, tokens, nodes, child edges, interned names and spelling bytes, types, generic copies, pending tasks, diagnostics, output chunks, recursion bytes, steps and concurrent jobs. Give each builder separate row/payload limits and impose a total batch/admission budget. Source bytes alone do not bound repeated type expansion.

Fixed collection capacities belong to types: a command-line option cannot silently enlarge them. Ship conservative compiled ceilings with lower operational limits; document larger-build profiles. Only use input-derived builder formulas where proved, as DESIGN requires. Report the exhausted resource and remedy; never emit a successful truncated program. Batching bounds temporary work but cannot erase cross-file dependencies. This is practical for a declared project-size envelope; measurements must establish whether worst-case reservations and padded layouts are affordable.

**Bootstrap and decision**

Keep a pinned Rust-written `nlc` as stage 0. It compiles the next-lang compiler source into stage 1; stage 1 compiles that same source into stage 2; stage 2 produces stage 3. Require identical stage-2/stage-3 IR and reproducible binaries with fixed clang, runtime, target, flags, paths and metadata. Agreement shows stability, not correctness: compare behavior and diagnostics against Rust over valid, invalid, generated and limit-boundary inputs, at development and release optimization levels.

First self-host a standalone lexer/parser and diagnostic formatter as the planned parallel-tool benchmark. Expand to checking, then IR emission; retain the Rust driver initially. Start that experiment after M3 and required collections; require step 6 for parallel sharing. Authorize a full rewrite only after validation and measured maintenance benefits. Main risks are duplicate compiler upkeep, distorted language priorities, bound-related usability failures, generic build-time growth and mutually reinforcing compiler bugs. Preserve Rust as an independent reference until those comparisons justify retiring it.
