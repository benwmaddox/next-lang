# Sol: T13/T14 review, round 1

1. **Biggest risk: the emitter assumes expressions produce self-contained values.** In `compiler/src/emit.rs`, `emit_expr` returns one computed value; locals and hidden temporaries use entry-block `alloca` (native-stack allocation), calls return aggregates (whole records/collections), and branches merge values with `phi` (selecting the arriving branch's value). Adding an Ascii pointer/length descriptor alone creates dangling pointers, accidental shared copies and extra temporaries. Introduce destination-directed emission: an expression can build into specified storage. Carry destinations through calls, concatenation, `if`, `match`, returns and Option/Result payloads. Plan stack ownership before emission. Extend `lower_signature` into complete argument/result-passing rules consumed by definitions, ordinary/optional calls, calls through function values and entry wrappers; ordinary calls currently construct arguments separately. Copy results before resetting scratch (temporary storage); never reset caller-owned output storage. LLVM cannot infer this ownership transformation.

2. **T13 is too big; split by representation changes.** Deliver stack contracts and context/runtime first; then fixed scratch and caller destinations for existing collections; then Ascii storage, byte copies, restricted moves and complete scope cleanup. T14 adds append generation and loop-growth proofs. Establish destination-directed emission before Ascii so T14 does not replace its implementation. Keep T13's temporary ban on growing outer loop values explicit. T11 defers function-type stack contracts to M3: schedule them here, including compatible targets' maximum window and append capability. Do not silently analyse direct calls only.

3. **The literal worked example cannot be T14's acceptance fixture.** It needs Ascii fields in bounded storage, deferred to T15, plus shared snapshots not supplied by T08. T13 also never explicitly adds `ascii_upper` or `Ascii.empty()`. Supply a runnable T14 equivalent using read Ascii/count parameters and a bounded range; defer the original fixture to its storage/snapshot prerequisites. Specify expected contracts: `render` and `line` need scratch window `k=1`; `ascii_upper` and `str` need `k=0`, excluding their caller-owned destinations. With destination 0, base 1, N=2. Concatenation must stream pieces into output; eagerly materialising `str` while `name` occupies stack 1 needs another stack.

4. **DESIGN's “first free stack” is ambiguous.** With caller values on stacks 0 and 2, base 1 can collide with stack 2 and violates the rule that caller parameters lie below base. Answer: place the callee window above every caller growing-value stack reserved at the call, including its destination; reuse holes for locals only when safe. Define whether fresh/append versions have separate windows; compute both and publish their conservative maximum initially. N counts highest reachable index plus one, including fixed scratch, not merely simultaneous values.

5. **Maxima need executable inference rules.** `Ascii.empty()` cannot permanently infer `max 0`; answer: infer its builder maximum from an annotation, result destination or counted loop. Literal maxima are exact lengths; `str` includes a minus sign and uses proven integer ranges: six digits for `0..=999999`, eleven for unrestricted `int`. Check maximum arithmetic for overflow. Specify widening maxima and bytewise dictionary-order comparison. Proposed modes: `write` mutates without increasing length; `grow` also permits extension. Define ownership for `Option<Ascii>`/`Result<Ascii,E>`: T13's `fit` already requires wrapped growing values.

6. **Separate declared capacity from reservation exhaustion.** DESIGN requires ordinary append to be proved within capacity, otherwise explicit `try_append -> Result<(), Full>` with handled failure. T13/T14 omit that operation and could accidentally implement capacity overflow as job failure. Adopt that distinction; failed checked append preserves bytes, length and stack top, including when a helper fails after producing a prefix. Reservation exhaustion alone calls `nl_fail`. Define how a fallible producer participates in append mode; plain Ascii-returning functions currently have no recoverable failure channel.

7. **Two tests cannot express their stated intent.** Every T13 Ascii already has a maximum, so T14's unbounded-growth case needs an explicit inference failure for an unannotated builder, rather than a bounded value in an unbounded loop. T13's deliberately unbounded runtime growth also contradicts its outer-growth ban. Exhaust a small test reservation using a legal bounded value instead. A million tiny temporaries fit within 64 MB even without resets: make cumulative leaked bytes exceed the test reservation while legitimate peak usage stays below it.

8. **Cleanup requires ownership, not just loop hooks.** `TBlock.scope_id` exists, but `emit_iteration_cleanup` is only a comment; ordinary block exits lack releases. Track saved tops and owned stacks for every scope and every exit, including tail expressions, failed expectations and `?` outside loops. `take` transfers the stack slot and cleanup responsibility; reject moves that cannot preserve them initially. Test branch-dependent moves and reuse after a move. T02 has nearest-loop breaks only: replace T13's “break out of two loops” with nested-loop breaks plus return/`?` across both, or explicitly add labelled breaks.

9. **Fixed scratch must cover hidden storage too.** `check_large_local_types` limits parameters/results as well as locals; lifting its 64 KB rejection is insufficient. Construction, printing, equality, payload extraction and sorting can allocate native temporaries or pass huge aggregates by value. Route large backing storage through fixed scratch and address-based calls/results. Use a separate fixed-scratch stack with nested saved tops, counted in N when used. Test large nested collections copied/returned after their source scope ends, outer lists surviving iteration cleanup, and sorting scratch. Count alignment and simultaneous caller/callee allocations.

10. **Pin performance and remaining acceptance coverage.** “Keeping it fast” requires tops cached in registers, synchronised before relevant calls/exits and reloaded after callees grow them. Check IR (compiler output before machine code) for stack-table traffic on every byte append. Emit `noalias` (a non-overlap promise) only with proof. Add grow-parameter forwarding, hidden-destination overlap, embedded ASCII NUL printing/comparison, integer extrema and scratch-copy peaks. Assign UTF-8 boundaries to T15 and byte-peak reporting to T16. Child exit cannot test failed-job stack-set reuse: defer until pooling exists. Specify Linux reservation/guard-page failure handling and test-only override compilation; the driver always compiles the same runtime.
