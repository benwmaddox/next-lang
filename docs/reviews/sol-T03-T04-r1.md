# T03/T04 review, round 1

1. **T03 optional chaining conflicts with DESIGN, “`?.` and `??`”.** DESIGN says `some(f(x))`; T03 flattens an Option result. Follow DESIGN: `Option<T>?.f()` returning `Option<U>` produces `Option<Option<U>>`. Specify first-argument sugar for named functions (`x?.f(a)` calls `f(value, a)`); T01 has no user-method declarations. Reject Result receivers. Test receiver evaluation once, skipped arguments on `none`, nested Options, and chaining precedence with `?`/`??`.

2. **T03 propagation must preserve T02 exits.** Give `?` and `?? return` explicit return edges through every enclosing loop’s cleanup hook; `?? break/continue` target the nearest loop. Reject propagation and `?? return` directly in tests, as T02 forbids test-body returns; reject loop exits outside loops. Treat exiting alternatives as diverging when checking expression types. Test differing success types with identical Result error types, error-type mismatch, present values skipping fallbacks, and nested-loop exits.

3. **T03 constructor inference and matching need rules.** Infer missing Option/Result parameters from expected types; reject unconstrained `none`/`err(e)` instead of guessing. Context resolves unqualified cases; ambiguous cases require qualification. Evaluate the scrutinee once; payload bindings are immutable copies scoped to their arm. Require compatible reachable arm results; permit diverging arms. Bool needs both literals or `_`; integer matches need `_`; reject duplicate/subsumed arms and wrong payload arity. Test qualified patterns, shadowing, empty matches, cross-file case-name collisions, and block arms containing statements.

4. **Aggregate representation is underspecified.** Reject direct and indirect recursive value-type cycles, including through Option/Result. Define equality structurally by active case and payload, never padding or inactive payload bytes; no ordering yet. Pin nested enum/struct print formatting and declaration-order fields. Test unequal tags, equal nested payloads, unit payloads, copies, and failed expectations showing both operands evaluated once. Keep aggregate calls/results on T01’s shared signature-lowering path.

5. **T04 modes need storage compatibility.** A `write` argument must be an assignable place; plain parameters cannot be assigned or forwarded as writable. Require identical storage types for write arguments, including refinements and wrap/clamp policy: passing `Size` to `write int` would permit invalidating Size. A proof about its current value is insufficient. Test mutable fields, forwarding write parameters, scalar writes, temporaries/read parameters rejected, and refined write mismatches. Defer `grow` explicitly until growing values exist.

6. **Overlap must use owners and complete field paths.** “Two different fields” is insufficient: `s.a` overlaps `s.a.b`; `s.a.b` and `s.a.c` are disjoint. Reject repeated/ancestor places when either argument writes; allow repeated reads and independent copies. Track this through forwarded parameters; do not infer alias freedom from spelling alone. Add these cases in both argument orders, including nested calls with side effects; preserve T01’s left-to-right evaluation.

7. **Initialisation conflicts need resolution.** T04 requires every field without a default; DESIGN’s “Initialised before use” only explicitly requires an error when no valid zero/default exists. Keep T04’s explicit-field rule for M1, but declare that stricter subset. Reject duplicate/unknown fields and self-field reads in initialisers/defaults; resolve ordinary outer locals normally. Evaluate supplied fields in source order, then omitted defaults in declaration order, once per construction. Test overrides skipping defaults, nested required fields, invalid refined defaults, and immutable nested writes. Explicitly defer globals, restored state, and completed-value relational invariants.

8. **Refinement proofs must survive mutation soundly.** Kill narrowed facts on assignment/write calls; join branches conservatively and account for loop backedges. Bound checked arithmetic only on successful paths; wrapping arithmetic needs conservative ranges. Add two-argument `min(a,b)`/`max(a,b)` builtins with matching base types; earlier tasks provide none. Test stale proofs after mutation, early continue/break, refined loop bounds retaining T02’s base counter typing, and every store boundary, including enum payloads and returns.

9. **Range edges need acceptance tests.** Reject empty/reversed/out-of-base bounds; named types are aliases. Normalise `..` before wrap/clamp. Use widened arithmetic for wrapping differences/widths, including full-width long ranges. Test endpoints, negative modulo, singleton ranges, argument/return stores, successful/failed casts and fit, compile-time invalid constants, and arithmetic overflow before clamping. Preserve explicit base-width conversions.

10. **Split T04 constants into a follow-up task.** DESIGN “Effects” permits compile-time calls only to cacheable functions, not every pure function: reject write/grow parameters and transitive effects. Allow forward constant references; reject dependency cycles; impose a deterministic evaluation step limit with a build error. Reuse checked arithmetic/control-flow semantics. Test indirect print, cycles, call-chain failure locations, loops/match, and compile-time/native agreement. Land structs/modes before refinement analysis; extend Option/Result payload support to structs/refinements there.

11. **Resolve stale contract language explicitly.** PLAN M1 says “checked on store”; DESIGN’s earlier range paragraph says an out-of-range store fails. Follow the newer “The refinement contract”: unproved plain stores are build errors; only written casts/fit introduce runtime checks. Defer LLVM fact emission to M4, rather than silently widening T04 into optimisation work.
