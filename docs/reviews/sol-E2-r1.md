**Verdict: revise before implementation.** The feature selection is sensible: value aggregates and sums give the core library useful error handling without requiring collections or writable parameters. Behavioural comparison, independent layout, active-payload copies, and the two reference fixes follow PLAN items 3 and 5. However, declaration-only eligibility does not close the subset, the proposed emission bound is invalid, and pointer operands need an explicit snapshot rule. The reference also needs broader unit-value fixes.

1. **P1 — The 4,096-byte check misses inferred types.** Rust's `check_builtin_constructor` infers `some(x)` without an annotation (`checker.rs:6244–6285`). A declared 4,096-byte `S` passes eligibility, but `let x = some(s)` exceeds the cap; repeated `some` creates further types absent from declarations. `.ok()` also synthesises an `Option` (`checker.rs:8213`). Thus the layout table cannot be complete immediately after declaration phase 3. Tests ending in an inferred `Result` pose the same staging problem for unsupported classification. **Recommendation:** cover every instantiated value type, including intermediate expressions, and define when inferred layouts are interned. Specify how typed eligibility preserves unsupported-before-checker-error precedence, or explicitly revise that precedence; a declaration scan alone cannot supply this contract.

2. **P1 — Make declaration sizing finite and deterministic.** A short chain of structs containing two previous structs produces exponentially large finite sizes. Unknown names, duplicate declarations and recursive paths also precede the real checker. Rust separately detects cycles (`checker.rs:3548–3609`) and uses checked size arithmetic (`2442–2705`). **Recommendation:** use an iterative, memoised dependency walk, distinguish unresolved/cyclic types from known zero-sized types, and saturate finite sizes at 4,097, including alignment. Treat ambiguous type resolutions as unresolved rather than guessing and manufacturing an unsupported result. Pin direct, mutual and Option/Result cycles, forward references across files, padding-driven threshold crossings, and enormous finite declarations. State that this threshold uses E2's layout, not Rust's packed sizes.

3. **P1 — Pointer arguments must preserve evaluation-time copies.** “Nothing writes during the call” is insufficient. In `f(s, { s.x = 9; 0 })`, the first argument's value must precede the mutation in the second argument. Passing `s`'s slot directly observes the mutation. Likewise `s == { s.x = 9; s }` needs the original left operand. Rust's small aggregate operands are loaded as values before later operands (`emit.rs:21198` and call lowering). **Recommendation:** snapshot aggregate arguments and operands at their evaluation point, conservatively into fresh slots unless stability is proved. Add both mutation examples, constructor arguments and expectation failures. Retain the fresh hidden result destination for `s = f(s)`.

4. **P1 — Storage size does not bound emitted traversal code.** The budget's proposed cap-times-node-count derivation fails for `E0 { A(int), B(int) }`, then successive `En { A(En-1), B(En-1) }`: storage grows linearly, but expanding every case recursively for copying, equality or printing grows exponentially. Empty structs also permit arbitrarily many zero-byte leaves. Rust's printing/equality emitters recursively expand type structure (`emit.rs:16649,18614`). **Recommendation:** share generated helpers per type/operation, or derive and enforce an explicit expansion/work bound. Cover the entire type graph and all alternatives, defaults expanded at uses, labels and metadata; add adversarial DAG and zero-size fixtures. Increasing the per-node constant is insufficient.

5. **P2 — A per-value cap does not bound native frames.** Entry allocas for every aggregate local and temporary can collectively exhaust the native stack, including along an acyclic call chain. `core-library.md:337–339` assumes the kernel's ordinary 8 MiB stack suffices because E1 has no recursion; E2 substantially weakens that assumption. **Recommendation:** measure aggregate frame sizes and maximum call paths, add a many-live-values stress case, and specify a checked frame/path budget or record native exhaustion as an explicit limitation requiring a follow-up. Keep computed compiler stack bounds, target native frames and observed RSS separate.

6. **P1 — Integrate the default-scope fix into the main contract.** Declaration scope is the right correction, but “Struct literals”, “Not part of E2” and the checklist still instruct copying or merely reporting the old behaviour. Both explicit literals and `default_typed_value` check AST defaults in the current environment (`checker.rs:8404,10789`). **Recommendation:** replace those instructions and specify the default-checking phase after the declarations it may reference are registered. Settle whether unused/overridden bad defaults are checked eagerly, define field-naming diagnostics and multi-file anchors, and isolate defaults from caller locals, loop exits, test context and return type. Preserve runtime source-order overrides followed by omitted defaults, and attribute default calls/effects/cycles to uses. Test forward calls, shadowing, invalid unused defaults and overridden side effects in both compilers.

7. **P1 — Unit handling needs more than a format fix.** Stored unit printing reaches `emit_print_value_storage`'s generic load (`emit.rs:16798`), while `llvm_type(Unit)` is `void` (`typed.rs:934`): this emits invalid `load void`, not merely different bytes. Independently, named unit payload bindings are recorded as slots; `record_slot` and the function prologue do not erase unit storage (`emit.rs:7433,6645`). Unit parameters similarly lower to `void` parameters (`22108`). **Recommendation:** fix Rust's unit erasure for bindings, locals, parameters and calls as well as storage printing, then pin `Wrap(())` nested in a struct/Option, `some(())` matched with a named binding, and unit arguments. Evaluate unit expressions for effects but emit no unit loads/stores; equality of unit payloads is true.

8. **P2 — The byte layout is sound, but E3 needs an address abstraction.** Aligned fields, an i32 tag, per-case offsets, active-leaf copies and fresh results work without LLVM struct types or memcpy. Set empty-struct alignment explicitly to 1, and convert SSA booleans consistently to/from their byte storage. Native-stack pointers survive calls in E2. They cannot simply become retained pointers into moving regions: DESIGN “The job's data stack” includes read references and hidden destinations in its offset rule. **Recommendation:** centralise slot/field addressing now; E3 must retain offsets, reload the base after growth, and derive addresses only for accesses. Constant field offsets remain reusable. “No memcpy” should constrain emitted IR, allowing LLVM to select libcalls outside the protected memory closure.

9. **P2 — Pin actual first-error and match control-flow rules.** The spec says `?` checks its operand first, but Rust rejects `?` in tests before visiting the operand (`checker.rs:11000`). Match bindings can also fail declaration checks before their bodies (`checker.rs:11488–11512`). Current selfhost eligibility compares offsets without comparing file IDs (`compiler.nl:1158–1184`), contrary to E1's stated file-first order. **Recommendation:** add competing-error fixtures for these cases and constructor/local/function/case name collisions, rather than rejecting builtin-case spellings indiscriminately. Keep exhaustiveness last, test each missing-case order, duplicate payload names, and all-`never` matches; aggregate joins need destination copies and no fabricated predecessor or continuation when every arm terminates. For `?`, use the enclosing sum's layout even when its success type differs, copying only the failure payload before returning; cover unit and aggregate errors.

10. **P2 — Test wrapper retirement and hook behaviour, not just spelling.** `core/output.nl` uses raw `ioctl`/`statx` success checks, and `environment.nl` ignores `close`'s result; neither is caught by grepping `sys.is_error`. Writes also pass through fault injection and EINTR/short-write loops (`output.nl`, `format.nl`). **Recommendation:** require raw fallible syscall use only inside wrappers, preserve errno numbers and existing ignored-error policies, and rerun fault-sequence/output/startup tests. Preserve fixed C hook signatures separately from internal aggregate-result helpers. Test every new hook's bytes, flush order and failure status against C, including redirected output and buffered values between expectation labels. Keep the memory-function closure aggregate-free and verify its transitive post-link calls.

11. **P2 — Tighten classification and measurement acceptance.** Independent hand classification, expected files, reference-first execution, rejection-without-IR, and S2's default/long split are appropriate. “E1 packages keep their classes” conflicts with reclassifying every package: newly valid struct/enum fixtures and tests may also move. **Recommendation:** reclassify from the final corrected spec across all four roots, list every movement and expected-output change, and require long-mode O1/O3 plus C-leg success. Measure scalar regression against the same S2 baseline, aggregate compile/link costs and IR sizes, plus runtime with a checksum and controlled process/I/O overhead. Report best-of-five conditions and variability; avoid E1's subtraction of independent build timings as a compiler-only measurement. Stack reservation differences remain unobservable only under the documented fixed environment.
