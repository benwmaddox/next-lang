# Sol: M3 review, round 2

The five-task order can stand, but the acceptance cases still contain forward dependencies and conflicting requirements. T16 and T17 need the rules below before implementation.

Here N is the total stack count; k is a function's scratch-stack count (its window). A code point is one Unicode number, not necessarily one displayed character. A descriptor records where bytes live and their length; rollback restores the previous value. The native stack holds ordinary function-call frames.

1. **Round 1 disposition.** Destination-directed emission (building into supplied storage), complete call lowering, cleanup ownership, fixed scratch (temporary storage), conservative call windows, wrapped values, maxima (declared length limits), checked append and tests for accumulating temporary bytes are now assigned. Remaining gaps include the worked fixture, test-runtime configuration, byte bounds through function values and proved `noalias` emission (LLVM's promise that pointers cannot overlap). Calling the old review “binding” does not resolve contradictions below.

2. **T15's fixture still depends on T16.** Arrays of `Ascii` need collection payload support too; the proposed workaround changes nothing. Give T15 a fixture with a counted loop over integers and move the collection fixture definitively to T16. Its two parallel lists can have different counts: indexing `counts[i]` is not proved safe. Use one bounded list of rows or enforce equal counts. Restore DESIGN's explicit `let name = ascii_upper(...)`: the revised streamed expression can eliminate that temporary, so `k=1` and stack 1's 60 bytes no longer follow. For N=2, borrow collection storage without copying; constructing a large local input also needs fixed scratch, which counts in the entry's N.

3. **T13's runtime specification conflicts with itself.** N already includes fixed scratch; “N data stacks … plus one” counts it twice. Allocate it only when used and report it consistently. `PROT_NONE` means inaccessible memory; touching it does not automatically commit a usable page. Specify writable storage backed as pages are touched, an inaccessible guard page, and explicit limit checks calling `nl_fail`. The driver already passes `NLC_TEST_BUILD` for `nlc test` (`compiler/src/driver.rs`); use that switch rather than “built for cargo test.” Move tests of gaps between growing values' stacks to T14, where such values exist.

4. **T14/T15 must separate operations from append compilation.** T14 can evaluate `try_append`'s argument into scratch; rollback after a producer writes a prefix belongs to T15's append mode. Define how callers receive producer errors versus `Full`, and test both after a prefix. T15's unconditional rewrite of `s = s + piece` must retain T14's overlap handling when `piece` reads `s`. Define widening maxima explicitly. “Reservation exhaustion is the only job failure” must exclude explicit failing casts, already required by T14.

5. **T16 lacks parts of the text contract.** Add `Text bytes max N` and checked `Bytes`→`Ascii`. Define slice ownership and invalid-index behavior. `.bytes()` must be a temporary read-only view, usable as a parameter, never a writable alias or stored/returned reference. Append must enforce both code-point and byte limits; a `write Text` operation can keep its code-point length while needing more bytes. Test that case, embedded zero, malformed UTF-8, slicing boundaries, and failed conversions preserving their inputs.

6. **T16 field updates need failure safety.** DESIGN's Collections requires an oversized field write to return a handled error and leave storage unchanged. Specify staging and validation before publishing bytes or changing free lists, including multi-field replacements. DESIGN permits shrinking within the current slot; T16's test demands moving back to a smaller class. Choose the DESIGN behavior. View protection must cover the collection and enclosing values, including indirect calls, removal and shifting; checking only a view “of that field” is too narrow.

7. **T16 needs complete size accounting and value behavior.** “Under twice the largest class” bounds payload slots only. Include descriptors, lengths, free lists, flags, alignment and every enclosing capacity; reject overflow in multiplication, class rounding and page rounding. Test nested bounded text collections, copies surviving source cleanup, sorting and text keys in maps/sets. Copying slot descriptors alone cannot leave a copy dependent on its source's backing arrays. Explicitly refuse genuinely nested growing values as DESIGN requires; bounded collections remain allowed. Local collection pushes must not move stack tops.

8. **T17 needs an executable accounting rule.** Function types must carry byte bounds and native-stack bounds, not just T13's window count and T15's append flag. Calls through function values take the maximum across compatible targets. Count simultaneous caller storage, callee scratch, copy-down's old/new values and runtime-helper margins. Native-stack reporting is insufficient: either reserve/use that stack per entry, including guard and helper margins, or explicitly schedule the runtime support. LLVM frame sizes must come from the actual optimized target code.

9. **T17's acceptance cases need scope and units.** Define `stack_peak(f)` as a conservative total across data stacks, fixed scratch and native stack, excluding page rounding, and state how caller-owned results count. Keep T13's forced runtime-exhaustion test separate from T17's startup rejection of an undersized reservation. The supported subset has no stated legal unbounded source: use an analysis-only unknown-contract test or defer that executable fixture; never permit unbounded loop growth to exercise fallback. Report copy-down sites, as DESIGN requires.

10. **Unassigned scope.** PLAN assigns number parsing and bounded file writers to M3; none of these tasks owns them. Assign follow-ups with prerequisites. Explicitly defer snapshot-backed rendering, stack-set reuse and recursion support rather than imply M3 covers them.
