# Sol: M3 review, round 3

The reserve-ahead direction now matches the rewritten DESIGN sections. The task order can stand, but the points below need resolution before handing the affected tasks to Luna.

**Landed:** one data stack; regions (owned byte ranges); full reservations for interleaved builders; separate accepted length (published bytes) and allocation top (end of allocated storage); checkpoints (saved state for undoing an append), nested rollback, producer failure and reuse tests; iteration cleanup retaining accepted growth; moves transferring cleanup without moving bytes, with escaping moves refused; overlapping append/reassignment fallback; counting caller storage alongside callee storage, and old/new values while both exist. The former second-stack and 4 KB threshold for choosing copies are superseded, not missing. Recursion is explicitly deferred in PLAN and T17.

1. **T16's failure-safe update rule cannot always obtain its fresh slot.** At collection capacity, every element can occupy the same size class (slots of one fixed byte size). Replacing one field with another value fitting that class has no spare slot; inline fields have no slots at all. This conflicts with DESIGN's in-place writes and guaranteed legal updates at capacity. Stage and validate replacement bytes in temporary storage, then commit into the existing slot when it fits; allocate another class only when needed. Stage all fields before publishing a multi-field replacement. Count staging bytes and test same-class replacement at capacity, inline replacement, and a later-field failure preserving every old field.

2. **T15 still needs a usable fallible-append interface.** Naming producer error `E` and capacity error `Full` does not define a source expression or their return types. Give runnable examples for a producer returning `Result<Ascii max N, E>`, both with proved capacity and checked capacity, including `E = Full`. Specify propagation/handling and when append mode replaces T14's evaluate-first `try_append` path. Test prefix production followed by each failure and successful reuse.

3. **Native-stack policy remains optional and inconsistent.** T13 retains a large-temporary fallback to the native stack (ordinary function-call storage), although reserved builders can safely have data-stack temporaries above them. Remove that leftover or specify its trigger, byte accounting and per-iteration reclamation. T17's “reserve and switch, or report only” leaves a material implementation choice unresolved against DESIGN's per-job native reservation. Choose implementation or an explicit scheduled deferral. Function contracts must carry native bounds through indirect calls (calls through function values) too. Define 4 KB as 4,096 bytes and settle the equality boundary.

4. **Make future growth and overlap proofs explicit.** T14's “finished” must mean no future growth, following `take` and calls through function values: passing a packed value to `grow` must never overwrite a later live region. Add a moved-builder growth test with another live builder above it. T13/T14 should explicitly require proved `noalias` emission—LLVM's promise that pointer accesses do not overlap—including hidden destinations; distinct values alone do not prove separate bytes.

5. **Finish the fixture and remove stale instructions.** T16's one-line list substitution omits counts and input ownership. Supply a complete bounded row-list fixture, borrowed by `render`; include the input's backing storage in the entry-point total. Keep 40,000 + 60 + overhead as the rendering requirement above caller-owned input, not the entire entry's footprint. Fold T16's binding corrections into its contradictory shrink/view acceptance cases. T17 still points to nonexistent “N stacks per job”; DESIGN's final acceptance cases still require separated stacks/windows. Replace these with region/byte cases.

6. **Preserve suspension and recursion requirements in their follow-ups.** T13's cache rule must include calls that may suspend even without allocating. Defer scheduler tests explicitly: waiting jobs retain regions, provisional bytes, checkpoints and native frames; admission (limiting jobs to the memory budget) counts waiting jobs, and cancellation finishes I/O/writer cleanup before reuse. Recursion's later test must reject retaining *any* region, including large fixed values, across recursive calls, including indirect cycles. DESIGN's final “Decided” bullet still states only the weaker growing-value ban; its rewritten compiler section is stronger.
