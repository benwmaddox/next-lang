**Verdict: revise before implementation.** The six themes follow PLAN items 3–5, but E3a is still several substantial tasks, and the ABI, merge boundary and unbounded layout need decisions before parallel implementation. Source review only; no builds were run while Luna edits the compiler and harness.

1. **P2 — The revised E2 foundation is substantially sound.** E2 now covers inferred oversized sums, memoised cycle/unknown handling, active-payload copies, unit erasure, declaration-scoped defaults, shared helpers and evaluation snapshots. Aligned byte slots, an i32 tag at zero, payloads starting at **aligned offsets at or after 4**, fresh destinations and byte-stored bools work without LLVM structs or emitted memcpy. Its printing, structural equality, exhaustiveness-last diagnostics and propagation into the enclosing sum's layout are appropriate. **Recommendation:** retain those contracts and their adversarial fixtures. Do not revert to declaration-only sizing: `some(s)` and `.ok()` instantiate types during checking. The native-path budget remains a documented partial bound, not a stack-safety proof.

2. **P1 — E3a can avoid target sums, but delimiters do not establish a merge contract.** `discard push/insert` can lower directly to capacity branches without constructing `Result`; `remove`, `clear` and iteration need no sums. However, current `compiler.nl` identifies aggregates by `ty >= TY_STRUCT_BASE`, indexes `struct_types`, and shares signatures, helper emission and exit lowering with E2b/E2c. E3a changes all these assumptions. **Recommendation:** land a common type-kind, storage-location, helper and exit interface in E2a first; agree ownership of shared functions. Interpret “no Option/Result” as no new target dependency, since compiler source already uses them. Make merge validation include enums containing collections, collection-bearing defaults, and propagation while regions/views are live, beyond resolving comment-delimited hunks.

3. **P1 — The proposed single-form parameter ABI is incomplete.** E3's `write` section requires a collection/text parameter to receive an i64 stack offset, but E3e passes globals by address. A collection field in a small native struct also has no job-stack offset. E3e then passes flattened elements as collection-offset-plus-index, although an ordinary callee expects contiguous storage; nested lanes additionally need enclosing strides. **Recommendation:** specify one location descriptor covering storage origin and lane geometry, explicit callee variants, or gathering into contiguous regions with copy-back. Apply the choice to read parameters, `write`, `grow`, hidden results and helpers. Pin whole globals, embedded small collections, large struct elements and nested subcollections across relocation.

4. **P1 — Argument exclusivity does not make every copy invisible.** In `f(xs[0], { xs[0] = 9; 0 })`, with the first parameter `write int`, Rust's scalar element pointer observes 9 when the callee begins; E3's early native-cell copy can observe the old value. The second argument is not a place, so `places_overlap` does not reject it. Conversely E2's snapshot-copy shortcut assumes calls cannot mutate caller locals; `f(s, mutate(s))` invalidates that assumption. **Recommendation:** capture indexes once, distinguish evaluation-time read snapshots from references, and account for later argument effects before copy-in. Test both examples, equality and expectation operands. Audit Rust's struct-element gather path for the same reference-semantics discrepancy instead of assuming its equivalence.

5. **P1 — Region layout needs exact sizes, not E2's saturated sizes.** Current `size_add_saturated`, `size_align_saturated` and `size_package_structs` stop at 4,097. Removing the unsupported event would allocate the wrong space for larger structs. Mixed types also need a transitive rule: does a small struct containing a collection remain native? **Recommendation:** separate capped eligibility sizing from exact checked layout arithmetic; check lane products, alignment, metadata and region/top additions. Preserve unknown/cycle diagnostics. Keep the oversized-sum gate transitive through structs until E3b, including inferred instances after merging E2c.

6. **P1 — Nail down the growth/context boundary before preserving the C leg.** `core/context.nl::nl_context_create` currently returns the stack base without initialising a usable context record; C's `nl_data_stack_context` has a separate stable header and a particular field layout. Inline context accesses cannot use an arbitrary core struct while the same program IR links against C. Moreover core-library.md requires context passing before the first region-using core function, whereas E3 delays it until E3d after text results arrive. **Recommendation:** define and check the compatible context prefix, stable header, guard ownership and failure cleanup. Either keep every pre-E3d core helper region-free explicitly or advance the ABI switch. Add `clock_gettime` for growth timing and specify non-heap poison-record bookkeeping. Keep the two-phase syscall-address relocation test mandatory.

7. **P1 — Wrappers and stack-address syntax need joint design.** E2c permits raw fallible syscalls only inside wrappers taking `sys.Addr`; core-library.md permits `sys.stack_addr` only directly inside a raw syscall argument. Thus replacing `sys.write(...stack_addr...)` with E2c's wrapper is not mechanical. **Recommendation:** provide offset-taking stack-buffer wrappers that derive addresses inside the final syscall, alongside stable-address wrappers where needed. Include this in the E3a merge checklist and test the wrapper audit, injected EINTR/short writes and later-argument relocation together. Preserve fixed memory-function signatures and their protected call closure.

8. **P1 — Unbounded multi-lane storage has no specified implementation.** E3's bounded formula is `lane_offset + i * element_size`; the next lane begins after the preceding capacity. An unbounded list of two-field structs cannot extend both lanes at the tail without relocating internal bytes, reserving a finite maximum, or changing representation. The whole-stack `mremap` does not solve this. Return handoff also needs a top/cleanup protocol that survives normal scope resets. **Recommendation:** initially restrict unbounded elements to a single contiguous lane, or obtain a concrete layout decision consistent with DESIGN's no-copy promise. Specify return types, top ownership and the exemption from the ordinary loop-bound rule; add multi-field and nested-call fixtures.

9. **P1 — Several part boundaries are not closed.** E3c promises text stored in fields/payloads but E3e first implements text collection lanes: `list<S, N>` where `S` contains text needs an explicit earlier unsupported gate. `byte` is still excluded by E2, yet E3 needs it; Rust defines it as an int refinement (`Checker::new`). E3c includes `fit<Ascii...>` while “Not part” excludes `fit`. E3f promises ASCII reads although Rust's Fs-read checker accepts byte lists, Text and Bytes, not Ascii. **Recommendation:** enumerate these exceptions and their typed/syntactic events, including when sum-typed elements become supported. Include Utf8Error/TextError, Path/DirEntry and capability dependencies where required; remove the nonexistent list `get` fixture.

10. **P1 — Confirmed grow bug; distinguish append rollback from call rollback.** `string_width_fits(actual, expected)` tests `actual <= expected`; direct and indirect calls use it for grow arguments, opposite the advertised reservation requirement. Text needs both byte and code-point checks. The general call path additionally has Write-only mode/overlap branches. Separately, `emit_ascii_try_append` publishes each successful append immediately: a later propagated error does not undo earlier successful operations in the grow callee. **Recommendation:** audit duplicated call paths and fix the width checks with smaller/equal/larger fixtures, retaining same-kind restrictions. Limit checkpoints to append transactions; pin a grow helper that appends successfully and then returns an error before promising call-wide rollback.

11. **P2 — The reference fixes are justified but need wider plumbing.** Bytes-only reads follow the adopted O5 decision; remove the checker overload, emitter branch and declaration as well as `nl_fs_read`. Zero-return writes must use EIO while negative returns retain errno; both `nl_write_all` and `nl_output_flush_index` contain the stale-errno expression. Inclusive slicing is indeed wrong: both parsers discard `RangeInclusive`, so emitter-only repair cannot work. **Recommendation:** preserve inclusivity through both parsers and typed lowering, retain parse parity, and guard endpoint overflow as kind 16. Keep E2's default-scope/unit fixes; their broader erasure and phase coverage should remain regression tests.

12. **P1 — Error order and compiler bounds need concrete extensions.** E3 says overlap checks follow argument checking; `check_direct_function_call` resolves each place and checks overlap **before** checking that argument's type, interleaved with earlier arguments. Fully expanded flattened lanes and evaluated constant-array bytes also are not automatically bounded by syntax-node counts or literal source bytes. **Recommendation:** pin the actual interleaving with competing errors. Derive bounds for representation expansion and constant output, or use shared schemas/compact emission; retain helper loops for live-element copy, equality and printing. Do not silently add compiler limits below stage 0's accepted input policy.

13. **P2 — Strengthen acceptance where the reference cannot help.** Hand classification, default/long modes, fresh expected files and direct measurements are appropriate. But relocation currently selects `build` packages, omitting E3d's new `expected` unbounded cases; unchanged stderr alone cannot prove a move occurred. C's stats line reports final reservation, not starting size, and inline bumps must update peak accounting too. **Recommendation:** require positive growth/relocation evidence, cover expected cases, expose initial size separately, and distinguish reserved/peak/written/resident measures. Split E3a's region runtime from collections/write acceptance milestones; similarly give the unique streaming writer its own milestone. Keep both full suites and merge measurements mandatory, without treating “one session” as a completeness criterion.
