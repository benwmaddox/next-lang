# Sol: T06/T07 review, round 2

The rewrite takes r1's split, operation contracts, stable Result typing, iteration snapshot, indexed overlap, construction, layout and copy-versus-view points. T07's refusal of pool copies/returns/resets is a permitted implementation boundary under DESIGN's “Later”; it does not implement DESIGN's eventual copy rebinding. The following still need resolution before implementation.

1. **Make pool restrictions recursive through enclosing values** (T07, Owner parameters). T06 permits copying and returning structs and collections; T07 only explicitly prohibits whole-pool operations. Define whether a local struct may contain a pool, how its owner is named (`state.nodes`), and reject copying, returning or replacing any aggregate containing one, including assignment through a `write` parameter. Otherwise replacing the containing struct can bypass reset rejection and revive ids. Test that bypass, a legal borrowed pool field, and pools nested through structs inside arrays/lists. Name the follow-up milestone for rebinding copies and returns.

2. **Resolve pool constants versus copy/return rejection** (T07, Constants). `const P: pool<...> = make_pool()` appears to require a forbidden return; reading a stored pool constant requires an owner/copy policy. Distinguish evaluating a function that uses a local pool and returns a scalar from materialising a pool-valued constant. Either defer the latter or specify its owner, uses and self-link handling. Compile-time/native agreement alone does not settle this. Schedule evaluator changes in T06/T07 after T05 lands.

3. **Complete the owner-parameter contract** (T07, Owner parameters). Add a complete helper body and inferred call using both `nodes.Id` and `Id<nodes>`. State that the third pool argument refers to the existing owner's identity and cannot attach it to new storage. Scope checks must cover storing ids into longer-lived values as well as returns, recursively through structs, enums and collections. Test repeated calls and loop creations attempting to carry an earlier instance's id into a later instance; a same-source-line success case alone does not establish freshness. Fix the instantiation limit and define whether owner substitutions consume it.

4. **Track nested views through all enclosing storage** (T06, Loops/Places). While iterating `units[k].inventory`, reject replacing `units[k]`, assigning `units`, removing/shifting its enclosing element, and invalidating helper calls. T07 must extend this to removing an enclosing pool element. These were explicit r1 cases but remain absent. Specify whether assigning a scalar loop binding (`x = 3`) writes its element, and test read-only rejection too.

5. **Specify cardinality transfer rules** (T06, Full/discard). Invalidating count facts after writes includes the very pushes needed by N-into-N. Define successful push as incrementing count, failure as preserving it, and joins/back edges conservatively. Add a bounded-loop proof, a mutation/helper invalidating that proof, and proved calls used with `?`/`unwrap`. Define `Full`'s constructible value and matching syntax.

6. **Explicitly carry T06 contracts into T07.** Apply stable Result typing, mandatory handling, `discard` and proven-success handling to `add`; require mutable storage for mutations. State zero/constant capacity rules and the temporary 64-KB storage limit for pools, including flags, generations, free-list storage and temporaries; size the 4096-node example accordingly. Add a pool containing nested lists with independent counts and flattened IR. T06 tests nesting only without pools; T07 currently never closes that DESIGN acceptance case.
