Verdict: **revise before implementation.** Lexer first, parser second is a useful split, but this spec promises parser behaviour from a lexer and assumes byte-buffer and filesystem operations unavailable today. T24 resolves exit status and literals, not those gaps. The comparison needs a lexer-only oracle and explicit adversarial cases; corpus comparison plus a few hundred mutations cannot establish every lexer difference.

1. **Blocking: `parse --tokens` is not a lexer-only oracle.** `driver.rs:213–257` always parses, counts trees and checks work before returning token output; `main.rs:43–55` merely selects which completed dump to print. The existing binary rejects `tests/parse/cases/bad_integer_separator_double --tokens` with status 2 and “underscores in integer literals must appear between digits”; lexing itself accepts that number. Parser failures in an earlier file also precede later lexical failures. **Recommendation:** retain S1a-1 as lexer alone, but provide a Rust lexer-only package adapter, sharing listing, byte/UTF-8 checks, token limits and formatting. Compare all packages against that adapter, including syntactically invalid ones. Restore full `parse` equivalence, including no flags/both flags, in S1a-2. Do not silently change existing `parse --tokens` semantics.

2. **Blocking: binding `Bytes` storage lacks essential access and construction APIs.** `checker.rs:9955–9974` permits indexing only arrays/lists. Bytes has slicing and conversion (`:6340–6420`), but slices retain the original maximum; it has no byte getter, push or bounded append. `grow`/`try_append` are Ascii-only; concatenation sums declared maxima (`check_string_add`), so repeated `source = source + file` cannot fill a fixed 64 MiB builder. This affects source accumulation and JSON output. `to_text()` reports `InvalidUtf8`, without Rust's `valid_up_to` offset. **Recommendation:** add a small prerequisite for byte access and checked bounded buffer construction, with overflow/alias tests. Specify a bytewise UTF-8 validator or an offset-returning validation API. Alternatively authorize concrete `list<byte, N>` buffers and accept their four-byte storage cost; do not leave Luna to discover a binding-design violation.

3. **Blocking: filesystem equivalence is currently impossible over the promised domain.** `nl_fs_list` (`runtime/nl_runtime.c:1470–1533`) bounds **all** directory entries before filtering and uses `AT_SYMLINK_NOFOLLOW`; next-lang exposes no following-stat operation. Rust filters first, follows symlinks and then limits 256 sources (`driver.rs:135–156`). Arbitrarily many ignored files cannot fit any chosen fixed listing capacity. Rooted I/O also refuses absolute paths and links outside the working root, which Rust accepts. **Recommendation:** provide filtered, bounded listing with following-file metadata through an explicit bridge/API, and define the supported rooted-path domain. Test `.nl` versus `a.nl`, `.NL`, `.nl` directories, regular/dangling/directory symlinks, 256/257 sources, and many ignored entries. Include invalid-UTF-8 names: Rust sorts raw paths but displays `<source>` for such basenames (`:165–169`).

4. **High: the stated limit order is wrong inside lexing, and token capacity is unspecified.** Spec line 15 puts the per-file token check after lexing. Rust checks on every emitted token (`lexer.rs:334–364`), including Newline and Eof; suppressed newlines never check. Delimiter errors occur before the corresponding token push, and unclosed delimiters precede Eof insertion. Package tokens are checked only after successful complete-file lexing (`driver.rs:199–213`). **Recommendation:** specify those exact points and diagnostic anchors. Reserve 5,000,000 token slots, or use a separate million-token file scratch; a four-million-slot package list can otherwise overflow before a later lexical error that Rust prefers. Record each file's token start/count. Specify the 16 MiB read temporary and map its capacity overflow to the source-limit diagnostic. Require paired-error tests within one file and across sorted files, plus every file/source/token/delimiter boundary, counting Eof.

5. **High: newline/operator coverage must be directed.** `lexer.rs:85–110,345–364` ignores CR as whitespace, retains comment-ending LF, suppresses LF only inside `()`/`[]`, and coalesces LF after either Newline or Semicolon. Braces do not suppress it; semicolons themselves are not coalesced. Three-character operators precede two-character operators (`:238–245,375–431`). **Recommendation:** add a compact matrix for leading/trailing LF, whitespace/comment-separated LF, CRLF/lone CR, semicolon sequences, nested/mismatched delimiters and EOF without LF. Exercise every operator, ambiguous prefix and truncated suffix. Use lexer-only inputs so parser rejection cannot mask token differences.

6. **High: spellings, decoded values and Unicode need separate assertions.** Numbers consume ASCII alphanumerics/underscores without numeric validation (`lexer.rs:140–160`); `0x`, `1__0`, `123abc`, suffixes and `1..=2` need span tests. Token dumps quote raw source, not decoded strings (`syntax_dump.rs:14–32`), so they cannot detect successful escape-decoding bugs. Before T24, `b"x"` is Ident plus String; T24 may change representation. **Recommendation:** freeze the post-T24 reference and test its actual kinds, valid/invalid/truncated escapes, newline/trailing backslash and opening-quote error anchors; defer decoded-value equality to parser tests. Require JSON control-byte cases (`\u0000`, lowercase hex), raw Unicode, and chunk-boundary quoting. Test byte columns after multibyte characters, tabs and CRLF; invalid UTF-8 must use sequence-start `valid_up_to`, including overlong, surrogate and truncated sequences. Unexpected non-ASCII characters currently format the first UTF-8 byte as a character (`lexer.rs:249–252`), an easily missed compatibility quirk.

7. **Medium: distinguish conveniences from prerequisites.** T18 already provides byte `is_digit`/`is_alpha`/`is_space` (`tests/test/t18_number_text`); however `is_space()` must not replace the lexer's narrower whitespace checks. List-capacity inference still lacks a list case in `unify_generic_type`; scalar constants and concrete parameter capacities work. Enums and exhaustive matches can represent token kinds; T11 fixtures demonstrate function values in arrays/lists and effect bounds. **Recommendation:** use concrete capacities, a TokenKind enum and explicit spelling matches initially. Function tables are optional, not a prerequisite; keywords are Ident tokens. Report forced boilerplate separately from missing byte APIs. Gate implementation on T24's completed report/acceptance rather than assuming its in-progress changes are present.

8. **Medium: make validation reproducible and measurements comparable.** `run_package_args` recompiles and invokes clang on every run (`driver.rs:493–518`); using it per corpus/fuzz case would measure builds. The research benchmark identifies aggregate counts but supplies no frozen generator/input selection, and today's corpus has changed. `inspect stacks` reports bounds/reservations, not measured touched pages (T17 report). **Recommendation:** build selfhost once outside timed runs; pass that executable and Cargo's reference executable into the harness without nested Cargo builds. Preserve binary stderr/status, mutation seed and failing input; normalize only specified tool-error text. Check empty stdout after a later-file failure, duplicate/unknown flags and the specified temporary `--tree` rejection. Commit a deterministic benchmark recipe/manifest, time equivalent lexer-only work, and report runtime touched/high-water data plus process RSS separately, including I/O staging and scratch storage.
