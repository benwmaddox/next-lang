Verdict: **revise before adopting the architecture or its PLAN changes.** The stack-based direction, sequential S1a, sequential name interning, and bounded emission waves are sound choices. Most implementation facts are right. However, the collection rule is unsafe as written, S1 does not yet preserve the reference's error order, and 35.4 MiB is an incomplete projection. This is a source review; no builds or network access were used.

1. **The implementation baseline is substantially correct.** `nl_claim_memory` touches globals even with overcommit allowed (`runtime/nl_runtime.c:468–507`). Empty collections, pool initialization, struct/enum construction and ordinary copies cover full storage (`compiler/src/emit.rs:6829–7001`). `byte` is currently an `int` refinement (`checker.rs:273–279`), refinements retain base width (`emit.rs:1505`), the default data reservation is 67,108,864 bytes (`nl_runtime.c:59`), and generic inference handles pools but lacks a list case (`checker.rs:7099–7139`). These agree with §2.3. Keep the distinction between implementation defects and DESIGN's promise of locals committed as used (`docs/DESIGN.md:191`). Qualify “no heap anywhere”: runtime contexts and directory listing allocate through `calloc`/`realloc`/`strdup` (`nl_runtime.c:142`, `:1013–1038`). Say compiler tables need no application heap.

2. **High: map occupancy flags alone are insufficient.** The proposed exception in §§2.3b/6 initializes one byte per slot. Lookup first reads an arbitrary **8-byte bucket entry**, with zero meaning empty (`emit.rs:3895–3900`); positive entries reference insertion-order records. Zeroing only flags leaves dirty buckets usable as bogus references. Initialize the bucket array, or explicitly redesign probing. Copies must preserve or rebuild buckets, tombstones (deleted-bucket markers), hashes and insertion order. Define initialization from actual metadata reads, rather than a flags-only exception.

3. **High: “live elements” needs a complete representation rule.** A pool's high-water mark means the greatest initialized slot boundary, not its live count. Guard lookup, iteration, equality and printing against that boundary before reading flags/generations; current lookup checks only capacity (`emit.rs:4789–4805`). Preserve removed-slot generations, retirement and free-slot order through copies and resets (`DESIGN.md:216–234`). Lists' comparison loops stop at count, but equality first stores whole collection operands (`emit.rs:9666–9675`); printing does likewise (`:8288–8293`). Audit whole-value loads/stores as well as explicit memory copies. Include wrapped queues/rings, nested collections, active enum payloads and fully live arrays/grids. Test dirtied destinations with stale pool ids, retirement, map tombstones, equality, hashing and printing; equal lists alone cannot establish safety.

4. **High: the memory arithmetic is correct; the modeled peak is incomplete.** Re-summing §4.6 gives exactly 1,390,632,960 reserved and 37,147,392 touched bytes. But §4.4's token-to-name-id array is absent: a dense `int` array adds 20 MB reserved and 2 MB used at the stated token counts. Add file boundaries, side-table references/attributes, the proposed 16 MiB read temporary, and measured printer-stack breadth; shallow trees can still push many siblings. Account for worker outputs coexisting with joined results unless fixed result slots permit direct construction (`DESIGN.md:447`). These are estimates, not current-runtime resident RAM: `fs.read` clears its entire destination on entry and failure (`nl_runtime.c:946–980`), and `fs.list` does likewise (`:1003`). Extend the live-only task into runtime I/O and update the byte-buffer layout exchanged with C. Report peak pages ever touched, including reused scratch, separately from current live payload. Today's 940,145,408-byte table calculation is also correct, but cannot execute on the default stack.

5. **High: S1's limit order is wrong.** §§4.3/5.1 say bytes, tokens, nodes, edges and work are checked after parsing. Rust checks per-file bytes, package bytes, UTF-8, lexing, package tokens, then parsing (`driver.rs:157–206`); tree counting and cumulative node/edge/work checks follow (`:207–240`). Thus exceeding package bytes/tokens beats a syntax error in that file. Correct the flow and slack argument. Preserve per-file tree-dump checks too (`syntax_dump.rs:113–128`). S1b must select errors by this sequential file-and-phase order, including read failures, even when jobs finish out of order.

6. **High: matching recursive functions does not bound native recursion to 1,000.** Rust has separate expression-call, parentheses, block, type and completed-expression-tree checks (`parser.rs:5–6`, `:383`, `:769`, `:1089–1115`, `:1698`). `else if` recurses directly without incrementing those counters (`:1902–1926`). A long chain can exhaust S1's native budget before Rust reaches its syntax diagnostic. Keep recursive descent where appropriate, but use bounded explicit frames for problematic chains or prove sufficient resources across the accepted input envelope. Reproduce the completed-tree diagnostic walk's order and operator spans (`:2126–2180`); depth summaries alone need an equivalence argument.

7. **Postorder storage and the proposed preorder printer work, subject to invariants.** Storing children before parents, then discovering children right-to-left and pushing them onto a stack, emits parents before children in left-to-right order. Require contiguous subtrees and construction in dump-child order, including `pool` arguments (`syntax_dump.rs:419–443`). Specify storage for generic names, decoded strings, magnitude references, refinement endpoints and synthetic nodes; `{kind, flags, token, span, subtree}` needs a documented decoding scheme or extra data. Prove the proposed two-nodes-per-token bound before relying on its slack. Hidden scope markers (§5.2) must not inflate reference node/edge/work counts. Retain file-relative offsets despite package-wide buffers (`syntax-tree-format.md:17`, `:29–31`).

8. **High: S1 lacks an exit-status mechanism and needs Unicode output.** `main` accepts only unit or `Result<(), E>` (`checker.rs:2824–2835`); an error prints a runtime prefix and exits 1 (`emit.rs:106–126`; `DESIGN.md:202`). That cannot directly implement parse's status 2 or tool-failure status 3 (`main.rs:89–98`). Schedule an explicit status facility or a specified driver bridge. Also, `Ascii` alone cannot buffer raw Unicode required by dump JSON (`syntax-tree-format.md:33`, `:79`; `DESIGN.md:586`). Use `Bytes`/`Text`, with UTF-8 validation before lexing.

9. **Magnitude limbs are sufficient, with overflow checking.** Four limbs (32-bit pieces) stored in positive `long`s avoid signed-half division problems; division by 10^9 has intermediates below signed-64 maximum. Parsing must detect carry beyond 128 bits, not wrap (`parser.rs:1941–1958`). Test decimal/hex/binary boundaries, underscores, both suffix cases, negative magnitudes, refinement endpoints and 2^128 overflow. No native `u128` feature is necessary.

10. **High: S2's frozen declaration phase has unresolved dependencies.** Sequential interning is deterministic and sensible; its 10 ms cost remains unmeasured. However, constants can call functions (`tests/run/t05_constants/main.nl:15`); Rust checks bodies and resolves calls/recursion before evaluating constants (`checker.rs:522–555`; `const_eval.rs:9–47`). Recursion contracts likewise require body call graphs. Split declaration registration from dependent evaluation/analysis, then specify bounded lists of pending tasks. When merging job-local types and generic copies, rewrite every referencing fact/instruction/request, not just type-table entries. Bound work as well as copy count. Also, §5.2's 10,000-call limit is call depth, not total calls (`const_eval.rs:6–7`).

11. **High: taking the smallest returned error does not produce the smallest source-position error.** Rust aborts declaration passes before bodies and each body returns its traversal-first error (`checker.rs:398–405`, `:522–538`). An earlier body error may never be discovered after a later signature error. Minimum reduction cannot recover undiscovered diagnostics. Prefer documenting a deterministic phase/function/traversal ordering compatible with the reference. A global position rule requires error recovery, dependency rules and tie-breaking, and is a separate language-tooling change.

12. **S3 waves need module ownership and a fuller driver bridge.** Per-file modules match DESIGN (`:744`, `:761`). Specify cross-module declarations, single ownership of globals/entry initialization and generic copies, and stable symbol numbering. Rust currently emits one global state/module (`emit.rs:131`, `:410`) and its driver measures optimized frames and patches recursion checks before final compilation (`driver.rs:576–599`). Merely invoking clang on S3 files omits that safety step. Include it in the bridge and memory/build-time measurements.

13. **Use precise bootstrap claims and reduce prerequisite scope.** Stage equality is PLAN's stability check (`PLAN.md:54`), not automatically an independent DDC test of stage 1 or a distributed executable. A diverse double-compiling interpretation must identify the candidate (potentially stage 3), trusted seed, source correspondence assumptions and trusted clang/runtime; IR equality alone does not verify executable correspondence. Keep binary comparison and behavioral tests. Prioritize findings 2–8 and typed-output/error-order contracts. List-capacity inference, config-field constants and literal tables are conveniences with concrete-capacity/scalar-constant workarounds, not hard S1 blockers. Packed lanes preserve declared arithmetic (`DESIGN.md:539`); separate that optimization from introducing primitive `byte`. Finally, the live-only task is already in current `PLAN.md:33`; update its acceptance criteria rather than schedule it twice.
