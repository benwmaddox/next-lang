# Sol: S0 review, round 1

**Verdict:** revise before implementation. T19/T20 cover the right missing facilities, but their ordering and safety contracts have concrete gaps. After those corrections, S0 plus M3 can support a bounded **sequential** S1. PLAN's parallel, frozen-pool S1 still requires the later builders/parallel work.

1. **T20 cannot use its argument API before T13 unchanged.** `list<Arg, 64>` reserves over 256 KiB, even with no arguments. `checker.rs::check_large_local_types` rejects locals, parameters and results over 65,536 bytes; `emit.rs` currently copies most read parameters and returns whole collections by value. Introduce safe borrowed argument access or bring storage-by-address support forward; merely exempting `Env` leaves oversized results/copies. T19 also needs the job context and compiler-added context arguments currently assigned to T13. Assign ownership of that shared groundwork now.

2. **T19's native-stack guarantee needs a build/runtime protocol.** A frame holds one call's return address and local storage. `driver.rs::clang` currently performs one `clang -O1` build, with no frame-size extraction. Specify how final machine-code frame sizes feed checks without subsequent optimisation invalidating them. Check before allocating the callee's frame; include calls through function values, compiler temporaries, alignment and helper chains without recursion. Define the recursion allowance separately from DESIGN's base requirement for calls without recursion. On the process stack, use actual remaining usable space, not total stack size. Include DESIGN's 64 KiB foreign-call margin and enough space to report failure. Test large frames, mutual recursion, calls through function values, foreign calls near exhaustion and supported optimisation levels. Reconcile test-child failure status with today's `nl_fail` exit 70 versus ordinary exit 1.

3. **Counting constant-evaluation steps is insufficient.** In `const_eval.rs::function_cacheability_problem`, results are saved only after visiting callees: an allowed cycle loops before evaluation starts. Compute purity (absence of effects) over whole call cycles; an effect anywhere must reach every caller. The evaluator's `call_function` recursively uses Rust's stack, so ten million permitted steps cannot prevent compiler stack overflow. Use explicit evaluation frames or a checked depth bound. Test terminating recursion, nontermination, mutual recursion with an effect, and a genuine constant dependency cycle, which must remain illegal.

4. **Define region ownership across a cycle.** A region is storage released when its owning scope ends. Distinguish newly retained regions at each recursion level from caller-owned source, token and node buffers merely borrowed by the parser. Demonstrate a recursive helper borrowing one large pool, and reject a per-level large local retained through recursion. Cover indirect and mutual cycles, hidden result destinations and temporary copies. T19's small tree-depth test alone cannot validate parsing. Require these cases again when T13/T16 introduce actual regions; checking only a direct self-call misses mutual cycles.

5. **T20 must finish the capability/effect contract.** A capability grants permission; an effect records its use. DESIGN requires manifest grants and has a closed effect set containing `log` and `env`, but no `out`; T11 currently spells output `print`. Decide the mapping, argument-access semantics and denied-grant errors. Define capability construction/storage rules so libraries cannot bypass explicit passing. Infer operation-specific effects through wrappers and function values, preserving permitted effect bounds and naming `fs.read` in constant errors. Future parallel bodies must reject these effects. Specify filesystem roots and whether absolute paths, `..` and symlinks can escape the test directory; changing the working directory alone does not isolate tests.

6. **Complete bounded I/O failure rules.** Define `fs.list` overflow and overlong-name behaviour, sorting by raw bytes, entry kinds and path joining. Specify buffer state after every read error, exact-capacity reads, embedded zero-byte paths, interrupted/short writes and output errors. Output must report failure, never successful truncation. State whether `args` excludes the executable and `--`: `main.rs` currently forwards `--` unchanged. Add boundary/error tests. Define M3 adapters for `Bytes`/`Text` and byte-list output; existing signatures do not automatically accept them.

7. **Give sequential S1 its own acceptance contract.** Keep source buffers in an outer scope; store token spans (byte offsets), pooled node IDs and child-edge ranges. Bound files, bytes, tokens, nodes, edges, diagnostics, nesting and work; report each exhausted limit. Specify UTF-8 rejection and byte-based columns matching `lexer.rs`. Match `parser.rs` integer decoding, including its 128-bit magnitudes, rather than assuming `parse_int` suffices. T14 supplies integer formatting; T18 is optional if decoding is implemented locally. Add a Rust parse-only command and stable tree format: today's driver immediately checks programs and exposes no tree dump. Compare syntax diagnostics separately from checker errors, over valid, malformed and boundary inputs. General generics (arbitrary type parameters), name deduplication, process launching and parallel sharing need not block this sequential slice.
