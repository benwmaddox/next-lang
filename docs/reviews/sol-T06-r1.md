# Sol: T06 review, round 1

1. **Split arrays/lists from pools and owner checking.** T06 adds SoA places, writable views, cardinality proofs, generative owners and generic definitions together. Land arrays/lists/layout/views first, then pools/owners. T03 permits only prelude generics; T06's `pool<Node<P>, N, P>` also needs capacity parameters. Specify `fn helper<P, N>(...)`, inference and instantiation limits; restrict this extension to owner/capacity parameters, deferring arbitrary type generics and traits. Give complete declaration/call examples, including `nodes.Id`, `Id<nodes>` and self-owner binding before checking `Node<nodes>`.

2. **Pool identity needs copy/reset rules now.** DESIGN “Owner parameters” requires fresh owners on copies, internal self-links retaining their bits, external ids still naming the source, and preserved generation history on reset; “Later” defers implementation cases. T06 silently inherits ordinary value copying from T04. Answer: explicitly reject pool copies, returns and whole-pool replacement/reset in this slice, with named follow-up coverage; read parameters borrow the caller's owner. Alternatively implement the stated rebinding rules. Test cross-pool assignment, external links, escaping ids hidden inside structs/Options, and repeated creation at one loop/call site.

3. **Nesting scope contradicts itself.** “Locals and parameters only” excludes fields, while the nested inventory case requires them; “structs of those” excludes collections. Permit collection fields in local aggregates and collection elements, including nested arrays/lists. Explicitly reject pools inside repeated elements, as DESIGN “Pools”/“Later” requires: an outer index cannot supply a distinct static owner. Test nested-list count independence, enclosing replacement under a live nested view, and the nested-pool diagnostic.

4. **Finish the operation contracts.** Define `insert(long, T) -> Result<(), Full>`, `list.remove(long) -> T`, `pool.remove(Id<P>) -> Option<T>`, and both counts as refined `long`. List insertion accepts `0..=count`; indexing/removal accepts `0..<count`; invalid indexes fail through T01's `nl_fail`, before stores or capacity checks. Stale/unoccupied/out-of-range pool removal returns `none` unchanged. Test empty pop/removal, endpoint insertion, shifting, stale double removal, exact capacity and unchanged contents after failure.

5. **“Skip the Result” must not change expression typing.** Keep push/add/insert Result types stable; permit an unused collection Result only when success is proved, eliminating the failure branch. Define the prelude `Full` case and `discard`: only collection operations' expected `Full` is discardable, not arbitrary Results. Test match/`?`/unwrap on proved calls, unchecked-result errors, explicit discard at capacity, and the DESIGN example of N pushes into a fresh capacity-N list. T04 intervals alone do not prove cardinality; specify this extra analysis and invalidate facts after writes/calls.

6. **Iteration during additions is unspecified.** Proposed answer: iterate entry-time elements in index/slot order; appended/added elements are not visited. Pin this before implementation. Element bindings are views, index/id bindings immutable; read parameters and `let` collections yield read-only views. End views at iteration exits, including T02/T03 break/continue/return/`?`, through existing cleanup edges. Test field writes reaching storage, additions during iteration, holes, nested loops, and removal after loop exit. Reject pop and invalidating helper calls while a view remains live.

7. **Extend T04 places beyond field paths.** Index writes must require mutable storage and preserve element refinements. Reject overlapping whole-collection/element arguments and uncertain indexes when either writes; allow proved-distinct indexes/fields, including forwarded write parameters. Test both argument orders, read-only forwarding failures, and fixed-field writes to another proved-distinct element while viewing. Evaluate receivers/indexes/arguments once, left to right.

8. **Construction and bounds need executable rules.** Give full declaration/fill syntax; evaluate fill once and copy it. Arrays require valid element defaults or a fill; lists/pools start empty without constructing unused elements. Reconcile array defaults explicitly with T04's required-field rule. Test refined arrays with/without initialization. Accept zero capacities; reject negative/nonconstant capacities, checked-long size-product overflow, and pool capacities exceeding slot32. The temporary 64-KiB limit must include metadata, padding, nested storage and hidden copies; prevent loop allocas accumulating. Mark native-stack storage above DESIGN's 4-KiB threshold as a temporary deviation.

9. **Close acceptance/representation gaps.** Test negative/count-bound indexes and explicit int-to-long casts; inspect pre-clang IR for guard elision. Use internal tests to fabricate out-of-range ids and near-retired generations, without adding id-forging syntax. Assert SoA lanes in IR. Proposed printing: arrays/lists `[1, 2]`, pools `pool{slot:generation => value}` in slot order. Equality compares active elements; same-owner pools compare occupied slots, live generations and payloads, ignoring free-list order, vacant history and padding. Preserve T02's once-only failed-expect operands. Extend T05 evaluation to supported collection operations in cacheable functions, or explicitly schedule that gap; compare compile-time/native results.

10. **Copies and writable access need examples.** `get(id)` returns a copy, so changing that result must leave the pool unchanged; writable loop views must update it. Specify whether DESIGN's `p[id].field` access is supported; defer it explicitly if loops are the only writable access. Permit small array/list results and independent copies, testing survival after the source scope ends through T01's shared signature lowering; retain large-local/data-stack cases for M3 as PLAN states.
