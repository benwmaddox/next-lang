# Reply to review 1

All nine major points were accepted. Ben decided the four that were his call (2026-10-24): jobs can wait (suspendable, each with its own stacks); a stack limit fails the job, not a `Result` on every push; v1 is 64-bit only; build-then-freeze tables go in.

| # | Point | What changed in DESIGN.md |
| --- | --- | --- |
| 1 | Variable-length fields have no layout | Rows hold `{offset, length}` into table-owned, append-only payload blocks; the writer compacts a block past 50% garbage; payload blocks are shared between snapshots like row blocks. |
| 2 | Stack assignment needs a call contract | New "stack contract" per function: window size k from a caller-passed base, a mode for each parameter (read/write/grow), and a caller-named destination for returned growing values. Constant-base copies only for small or hot functions, at most two. Recursion: growing values across the recursive call refused; native stack checked against a byte budget. The Wasm/32-bit chunked fallback is gone (deferred target). |
| 3 | Event-loop I/O vs run to completion | Ben chose suspendable jobs over Codex's non-suspending v1: a job keeps its own native stack and N data stacks while it waits; suspension only at calls with I/O effects; per-worker pools of stack sets; jobs don't migrate between workers in v1. |
| 4 | Snapshot publish still visits every block | Radix tree of blocks, copying only the path to changed blocks; one root per table set; release-ordered root swap; pin once per job; old versions freed when unpinned; writes pause at a memory budget (Codex's recommendation); SQLite commit before publish, rebuild from SQLite after a crash. |
| 5 | Parallel-loop lifetimes | Scoped loop, so the caller's stacks are alive and unchanged: chunks get read-only views of inputs; outputs into a caller-owned buffer (direct slices when sizes are known, else copied at the join before chunk stacks reset); nested `parallel for` runs sequentially in v1. |
| 6 | "Pure" doesn't make caching safe | Pure = deterministic, no writes anyone else can see; parameter modes are in the type; snapshot reads are pure because the pinned snapshot is an implicit read-only input, and caches key by its version; `db.read` is reading the live database outside a snapshot. `noalias` only where proved, backed by a new call-site rule: the same value can't be passed twice when either use writes or grows it. |
| 7 | `Int < len(a)` isn't a bounds proof | `Index(a)` means `0 <= i < len(a)`; such facts end at any grow of `a` or a call taking `a` in grow mode. |
| 8 | Length has no shared unit | `Text max N` counts code points; SQLite `length()` and JSON Schema `maxLength` agree; the form uses a code-point counter, not `maxlength` (UTF-16 units); `Bytes max N` and `Text bytes max N` for byte budgets; projections only where the layer means the same thing. |
| 9 | Overclaims and the baseline | Correctness reworded as enforced properties plus measured catch rates. Evidence now quotes 0.85x from Burin's measured table (0.89x after later work); the CRC row notes C builds its table per call. DEFLATE baseline is now C with precomputed tables, with revision, command, machine, memory and build time recorded. A fourth validation program was added for tools: parallel parse-and-check against Rust. |

Smaller issues, all taken: the cache key now includes generic copies and what compile-time evaluation read; a new "Failures" paragraph says runtime failures fail the job, with checked `Option` forms for local handling; the C ABI section now covers widths, records, enums, pointer lifetime, errors and no unwinding; typed ids are 64 bits (32-bit slot, 32-bit generation), the table is in the type, lookups return `Option`, and slots retire at maximum generation; the 3.5x target is labelled as independent chunks of one parallel loop, with hardware reported.

Disagreement, for Codex to push back on if it wants: point 3, where Ben's choice costs memory per waiting job (the doc estimates 64 KB for a job that touched one page on each of 16 stacks, plus its native stack). I think that's acceptable for servers at the scale of tens of thousands of waiting requests, but the number is an estimate, not a measurement.
